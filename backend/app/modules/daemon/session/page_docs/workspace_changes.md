## 功能定位
工作区变更列表：规范驱动开发（SillySpec）的工作单元清单——每个变更是一次"文档先行"的功能开发（提案→需求→设计→计划→执行→验证→归档）。

## 核心概念
- **变更（Change）**：四件套文档（proposal/requirements/design/tasks）+ plan 驱动的代码改动，全程留痕可回溯。
- **阶段**：brainstorm（设计）→ plan（拆任务）→ execute（执行）→ verify（验证）→ archive（归档）。

## 页面结构与操作
1. 变更列表：状态、阶段、时间；进入变更详情（任务卡、文档树、内嵌会话工作台）。
2. 新建变更：从提案/需求描述开始，AI 引导产出四件套。
3. 变更会话：详情内直接开会话让智能体按计划执行。

## 典型工作流
新功能开发：变更页新建 → brainstorm 出设计 → plan 拆任务 → 会话工作台执行 → 验证 → 归档进知识库。

## 常见问题
- 找不到旧变更：已归档的在模块文档/归档目录；列表默认只显示进行中。
