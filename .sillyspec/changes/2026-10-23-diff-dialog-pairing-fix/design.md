# 设计记录（Design Record）— 2026-10-23-diff-dialog-pairing-fix

## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

答：直接根因在 `collectTurnFilePatches`（frontend/src/components/daemon/file-changes/turn-file-diff.ts）的②回退配对：补丁行缺 tool_use_id 时，无主补丁被「按日志序塞给路径命中目标文件的第一个未用编辑调用」——它隐含假设「无主补丁都属于弹窗目标文件」，多文件编辑轮必然张冠李戴（2026-10-23 实证：会话 49c5c3ec / run 63130ca1，点 task-runner.test.ts 显示 design.md/requirements.md 内容，真补丁被挤掉丢弃）。修法把②回退改为**就近悬置配对**：单遍扫描日志，维护「最近的未消费编辑族调用」悬置游标；**新编辑调用到来时旧悬置判死清空**（串行协议推理：agent 工具调用顺序执行，新调用到来即证明前序调用 result 已处理——旧悬置必为补丁超 64KB 上限未附着 / result 行丢失的悬空调用，清空防其永久毒化后续配对）；无主补丁配给当前悬置，无悬置则诚实丢弃。协议依据：串行编辑轮 tool_result 紧随其 tool_use（sdk_pipeline 逐事件展开成行，daemon 按序上报），最近悬置调用即补丁归属；①tool_use_id 精确配对分支零改动。

选「就近紧邻」而非「修数据面补 id」的原因：数据面哪一环丢 id 未定（本地 transcript/rollout 均无 structuredPatch，取证只能靠平台日志接口——当日对长会话持续超时），前端就近配对在 id 缺失前提下独立成立且立刻止血；数据面问题登记 docs/sillyspec 活跃坑留待根治（FR-04）。

## 边界与并发（盲维四问——每问必答，答不了即设计缺口）

1. 乱序/迟到到达：输入或事件乱序时，本设计的假设还成立吗？

答：配对假设「agent 工具调用串行执行」（claude code SDK 交互会话协议事实：一次一个 tool_use，等 result 再下一个）。串行轮无主补丁的最近悬置即其归属，成立。**违反串行假设的真并发日志**（call A→call B→result A 到达）会把 A 的补丁配给悬置 B——已披露边界（见风险节），此类日志本身即上游协议违规，错配风险自担且仅影响无 id 数据面。SSE 流式下的迟到补丁行同理——落在日志流哪个位置就按哪个位置的悬置面判定，不回溯重算。

2. 并发写：两个执行体同时操作同一数据/文件会发生什么？

答：无新写面。本函数是纯映射（logs 只读→sections 新数组），弹窗每次 open 拉一次日志（AbortController 竞态守卫沿用）；无共享状态、无缓存。

3. 切换/生命周期：会话、请求或变更中途切换/中断时状态是否安全？

答：安全。无跨调用状态；弹窗关闭 abort 请求（既有）；重试按钮重建状态（既有）。就近游标是函数内局部变量，单次调用生命周期。

4. 作用域：跨工作区/跨仓/多实例时数据会不会串台？

答：不会。输入 logs 已按 sessionId+runId 圈定（弹窗 fetch 参数），路径过滤按仓根相对路径（matchesRepoPath 既有）；就近配对只在单轮日志内进行，无跨轮/跨会话状态。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

答：最大风险是**串行假设被违反的错配边界**——若上游真并发执行工具（违反 claude code 串行协议）且补丁行无 id，无主补丁会配给最近悬置（可能是别的文件）再经路径过滤兜底：错配内容只出现在「补丁真实归属文件」与「弹窗目标文件」不一致时被过滤掉，恰好同文件时无感、悬置文件的弹窗会显示他文件内容。定性：此类日志本身即协议违规+数据面缺陷双重异常，概率极低；对比现状（串行轮系统性张冠李戴）净收益为正。次风险：「无 id 补丁显示率下降」——悬置空（result 先于任何编辑调用）诚实丢弃；定性：错内容比没内容危害大（用户按错误 diff 理解改动会误导决策），且 id 齐全链路（①）不受影响。

试过放弃的方案：①修数据面补 id（根治但环节未定、取证受阻，当天无法交付止血，登记留档后另立变更）；②悬置>1 一律丢弃（首版实现）——真并发在串行协议下不存在，悬置堆积实为悬空调用（补丁超 64KB/丢失），一刀切丢弃会把悬空后的全部正常补丁拖死，放弃；③无主补丁按「补丁内容文件路径启发式」猜归属（structuredPatch 不带路径，伪归因，放弃）；④弹窗列出「本轮全部无主补丁」让用户自己看（把配对问题转嫁给用户，弹窗语义从「该文件的变更」劣化，放弃）。
