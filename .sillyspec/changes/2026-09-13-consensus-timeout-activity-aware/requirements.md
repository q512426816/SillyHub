# 需求规范：共识收口超时活动感知续期 + 状态卡名单/原因修复

## 功能需求

- **FR-1 活动感知续期**：sweeper 死线到点时，任一 pending 成员满足活动信号
  （影子最新 run status ∈ {running, queued, pending} 或该 run 时间线最近 2
  分钟有新行）→ `deadline_at` 顺延 60s 并更新状态卡「仍在工作，已延长等待」；
  顺延后死线不得超过 `created_at + 群 consensus_timeout_seconds + 600s`
  （硬上限）。
- **FR-2 无活动收口回归**：全员无活动时立即走原收口路径（有 delivered →
  超时收口注入；零 delivered → aborted），不得引入额外等待（2026-09-10
  收口语义回归）。
- **FR-3 名单去重与同名确定性**：任务 members 快照按成员 ID 去重；@ 解析遇
  同 display_name 多行时确定性选取（joined_at 最早）；卡面同名成员显示可区分
  （名字+id 前 6 位）。
- **FR-4 终态卡原因文案**：aborted/timeout 卡 content 含逐成员结局（触发失败
  原因/超时未响应/已交卷），汇总人自身状态可见；单行摘要 200 字符截断。
- **FR-5 触发失败落快照**：发送侧触发失败的成员在任务快照记 `state=failed`
  + 一句话 error 摘要（供 FR-4 卡面引用）。

## 非目标

- 终态复活/迟到意见补偿（D-5 明确范围外）；
- agent 执行链改造（方案 B 否决）；
- 前端渲染改动（卡面数据后端生成，前端零改动兼容）。

## 验收标准（对齐 design §4）

- AC-1：死线到点 + pending 成员有活动 → 不收口、顺延、卡面出现延长提示；
- AC-2：续期达硬上限 → 不再顺延，按原路径收口（意见/中止两分支）；
- AC-3：全员无活动 → 立即原路径收口，无额外等待；
- AC-4：快照无重复 ID；同名 @ 确定性命中一行；卡面同名可区分；
- AC-5：终态卡含逐成员结局（含汇总人）；截断内；
- AC-6：真实集成复验（uvicorn+PG）：>60s 长任务成员在续期下任务存活至意见
  交回并完成汇总；无活动场景回归原时序。
