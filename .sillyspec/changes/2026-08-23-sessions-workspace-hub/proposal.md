# 提案书（Proposal）

## 动机
会话门户（2026-08-22-workspace-sessions-portal 刚统一三入口、ql-20260822-010 刚做聊天优先表单）的"新建"仍是表单页心智：新建与聊天是两个界面，用户明确要求"点击新建直接到会话界面，和正常聊天界面一样，不要独立页面"。同时左侧平铺时间序列表无法回答"我在哪个工作区/哪台机器上聊过什么"，用户要求按工作区组织并参考 ZCode 客户端"工作区和任务"页形态。

## 关键问题
1. **新建≠聊天页**：NewSessionForm（哪怕聊天优先版）与 SessionPanel 是两个界面，体验断层；且后端 createSession 首句必填（prompt min_length=1）曾被认为是"必须先有表单收首句"的理由——预会话态证明发送动作本身即可满足该约束，零后端协议改动。
2. **列表无工作区维度**：会话已带 workspace_id 但全局列表平铺；工作区/变更 scope 入口虽能过滤，但全局视角下"按工作区找会话"无入口；机器/智能体维度也只藏在筛选里。
3. **会话条目信息不完备**：无创建人标识（共享场景预留，D-108@v2）。

## 变更范围
- 左侧 SessionListPanel 重构：两层筛选 tab（机器>智能体+全部）+ 工作区分组手风琴（组头「＋」新建、组内机器小节、创建人 chip、非工作区末尾组可新建、状态筛选与批量删除保留）。
- 右侧 SessionPanel 预会话态：sessionId=null 同构空态（同组件同布局），顶部锁定上下文行（工作区·机器·智能体，D-104 完全锁定），首句发送才 createSession 原地开聊（D-102），失败保留输入。
- 全部态新建两步轻选择浮层（在线机器→智能体，两步即达非表单）；筛选态直接带 tab 上下文。
- 后端小改：列表端点补 owner_name（join users）+ limit 上限 le=100→500（Grill X-07/X-08）。
- 入口收敛：全局完整树 / workspace 深链预展开 / change 独立页 preContext；NewSessionForm 三入口退役（D-109）。

## 不在范围内（显式清单）
- 不改 session/turn 生命周期与 daemon 协议（§7.5 生命周期契约表：零变更引用）。
- 不做会话内切换机器/智能体（D-004@v2 维持）。
- 不做服务端工作区聚合端点（客户端分组，D-103）。
- 不保留全局虚拟滚动（组内限高滚动替代，R-04）。
- 不把变更会话并入全局树（D-106）。
- 不做会话共享/多人可见（owner_name 仅字段预留，D-108@v2）。

## 成功标准（可验证）
- 点任一分组组头「＋」→ 右侧是与正常会话同构的聊天界面（无独立新建页/表单）；输入第一句发送后会话出现在对应分组且原地继续对话；不发言切走无新会话残留。
- 左侧按工作区分组展示（含非工作区末尾组），筛选 tab（机器>智能体）过滤生效，「全部」清空；条目含创建人 chip。
- 三入口行为不回归（D-001 契约）；?session= 深链直达；旧会话 owner 缺失 chip 显"—"。
- 全量 vitest / tsc / lint 通过；部署后三入口浏览器实证留档。
