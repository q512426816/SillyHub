# 提案书（Proposal）— 智能体会话流结构化重构

## 动机

/sessions 与 /runtimes 弹窗的智能体会话流无法让用户感知 agent 的真实执行过程：看不到实时进度、回复粘连为一整条、子代理工作完全不可见。数据链路（子代理归属/深度/工具类型字段）经查证已全链路落在 SSE 流与 DB 中，纯粹是前端展示层未消费——以最小代价（零后端改动）即可大幅提升会话体验。

## 关键问题

1. **实时进度缺失**：运行中轮次只有呼吸点动画。用户不知道 agent 在执行什么工具、跑了多久、有没有子代理在并行工作，长任务期间只能干等。
2. **回复结构丢失**：agent 一轮内「文本→工具→文本→工具→文本」交替产出，现有实现把所有文本 concat 成单条 markdown，中间穿插的工具位置丢失——读回复时不知道哪段结论对应哪次操作。
3. **子代理黑盒**：Task 工具 spawn 的子代理（调研/探索类任务的主力）内部思考与工具调用与主 agent 完全混流，归属数据在流里但前端丢弃，用户完全无法分辨哪段内容来自谁。

## 变更范围

纯前端改造（frontend_components / frontend_app / frontend_lib 三个模块，6 新增 + 7 修改）：

- 新建共享装配器（纯函数）：SSE 实时与历史恢复两条路径统一，收敛两处重复的日志处理副本，输出结构化轮次模型（文本/思考/工具/stderr 有序段 + 子代理按归属嵌套）。
- 渲染层 v2：段级组件（工具单行卡 + 运行中扫动动画、思考折叠行流式跟随、子代理嵌套块、流式光标）。
- 轮级状态条（计时/工具计数/子代理计数/当前活动）+ /sessions 页头部子代理目录（运行脉冲 + 点击定位）。

## 不在范围内（Non-Goals）

- 不改后端任何代码/接口/表结构（数据链路已完整）。
- 不做事件注册表/视图注册表/槽系统插件化架构（方案 B 已否决）。
- 不迁移 agent-log-viewer.tsx（/agent 日志查看器，非会话流场景）。
- 不做子代理 token 级计量（数据不存在，不编造显示）。
- 不改 Codex provider 行为（无归属字段，平铺与现状一致）。
- 不做跨轮 SillySpec 流程阶段（brainstorm/plan/execute）标注。

## 成功标准（可验证）

- 一轮回复按真实到达顺序渲染为有序段序列，文本段与工具卡交替可见，不再粘连单条。
- 运行中轮次显示状态条：真实计时（attach 恢复不归零）+ 工具计数 + 子代理计数 + 当前活动摘要；「对话」视图默认可见。
- 子代理的思考/工具/文本嵌套在对应 Task 块内可见；/sessions 头部目录列出子代理清单，运行中脉冲显示，点击定位展开。
- 旧会话日志（无归属字段）渲染与现状等价（平铺为主 agent）；Codex 会话不回归。
- sessions 页与 runtimes 弹窗两入口行为一致（共享组件 + 共享装配器，无双份逻辑）。
- 既有测试适配后全绿；新增装配器/段渲染单测覆盖分段、归属嵌套、override 撤回（含跨段）、归属桶配对、兜底合并。
