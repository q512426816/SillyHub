# 决策记录（Decisions）— 2026-10-27-netdata-prod-monitoring

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：答：最大风险是公网暴露——Netdata 面板无认证，若监听公网网卡且安全组放行即等于把全机指标公开。对策双保险：① 服务端只绑 127.0.0.1（应用层兜底，配置错误也不出网）；② 验收时从办公网实测 19999 不可达。次级风险：资源占用——官方口径约 1~5% 单核 + 100~400MB 内存，服务器余量 5.9G 内存，可接受；磁盘默认分层库上限约 1~2G，盘余 41G，可接受。试过但放弃的方案：① apt 装 Ubuntu 仓库版（v1.44 老旧，UI/容器插件弱于 stable 通道现版）；② Netdata Cloud 云端汇总（指标出网，与自托管诉求冲突）；③ 安全组放行 19999 限源 IP（家宽出口 IP 漂移，维护成本高且误配置即暴露，不如 SSH 隧道零暴露）；④ Prometheus+Grafana（运维成本高，单机秒级现场场景过重）。
