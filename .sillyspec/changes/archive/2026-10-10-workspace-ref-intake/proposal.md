# 提案书（Proposal）

## 动机

2026-10-09-attachment-inline-reference 已让用户把**已上传附件**以引用标签插入消息正文（uuid 精确锚定、同名可区分）。但会话大量上下文在**工作区文件系统**里：用户经常想指代「某个文件 / 某个目录 / 某文件里的某几行」，目前只能口头描述路径——各变更目录下大量同名 design.md 口头指代完全无法区分，智能体拿不到可寻址的引用。

## 关键问题

1. **无入口**：会话页工作区文件树（sessions-portal 文件模式）与右侧文件预览均无右键菜单，用户「看到文件」却无法「引用文件」。
2. **无锚点**：文件名会重复（同名 design.md 遍布 changes/archive），口头或纯名称指代必然歧义；必须绑定「工作区 id + 相对路径」。
3. **行级粒度缺失**：讨论某段代码时需要指到「某文件第几行到第几行」，当前预览区无行号、无选区引用机制。

## 变更范围

- 文件树右键文件/目录 →「添加到会话输入框」；预览区代码/纯文本分支加行号，选中行右键 →「添加选中内容到会话输入框（名称:起-止）」。
- 引用标签复用附件引用机制（attachment-refs 纯函数库扩展 + InputRefOverlay 镜像层）：类型角标区分文件/目录/代码块/附件，悬停显示完整路径绑定，同名 ·2 唯一化（附件/工作区两池合并）。
- 发送置换为 `[文件引用:wid|path]` / `[目录引用:wid|path]` / `[代码引用:wid|path|L起-L止]` 随正文透传（后端零改动）；历史消息解析三类标记渲染为可点击标签（点击打开预览）。
- 接入范围：单聊 + 预会话 + 群聊三输入区与全部发送组装位（2026-10-10 实测 7 处，实现前 grep 重盘）。

## 不在范围内（显式清单）

- 不做 .md 富文本态的选区引用（MarkdownText 渲染无行号概念；树右键引用整个 .md 文件不受影响）——D-002
- 不做代码引用历史标签点击后的滚动定位到行（增强项二期，本期仅打开预览）
- 不改后端 API / schema / 存储（引用为正文文本协议）——D-004
- 不做引用嵌套 / 拖拽重排 / 移动端长按入口
- 右键菜单本期各只有一项（重命名/删除等树操作后续扩展）
- 选中文本快照不进正文（指向语义：智能体按路径+行号读最新内容）——D-003

## 成功标准（可验证）

- 左栏文件树右键文件与目录节点均出现菜单，「添加到会话输入框」后在当前输入框光标处出现引用标签；单聊/预会话/群聊一致。
- 输入框内标签：悬停显示「类型 + 工作区 + 完整相对路径（+行号）」；右上 × 角标删一处；光标贴标签尾退格一次整删；同名引用自动 ·2 且与附件引用共用唯一化池。
- 预览代码/纯文本文件带行号；选中若干行右键出现「添加选中内容到会话输入框（名称:起-止）」，插入的标签行号与实际选区一致（反向选区/跨行选区正确）；无选区右键为浏览器默认菜单；.md/图片/PDF/二进制预览无选区菜单。
- 发送后智能体收到正文中的 `[文件引用:…]`/`[目录引用:…]`/`[代码引用:…]` 标记（路径与行号正确）；定时发送与团队直发路径同样置换。
- 历史消息中三类标记渲染为标签（图标+名称+行号），点击打开文件预览；本变更前的历史消息渲染逐字不变。
- 未插入任何引用时，输入区/预览区/发送链路行为与现状完全一致（零回归，既有测试全绿）。
