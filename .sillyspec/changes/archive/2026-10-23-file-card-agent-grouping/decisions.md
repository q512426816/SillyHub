# 决策记录（Decisions）— 2026-10-23-file-card-agent-grouping

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：答：最大风险是「本轮AGENT 0 个但 shell 很多」的形态——用户会先点开卡只看到空列表 + 按钮行，可能困惑；缓解：agent=0 时头部第一段显示「本轮AGENT 无直接文件编辑」（不渲染 +0 −0 假零），按钮行置顶显眼。次要风险：双段标题在一行 28px 内拥挤（长数字/窄面板），处理：两段间分隔符 + min-w-0 截断，两端 shrink-0。 试过放弃的方案：① daemon 侧给快照加「并行会话」独立归因（把 shell 再拆 command/parallel）——需要 mtime/进程级证据，daemon 现有采集拿不到可靠信号，放弃；② 前端按路径启发式猜并行会话（如 .sillyspec/ 前缀）——路径黑名单是伪归因，误伤用户业务文件，放弃；③ 两张独立卡片（agent 卡 + 其他卡）——把一个快照拆两张卡破坏「一轮一卡」的既有形态与测试锚，用户要的是卡内分组不是拆卡，放弃。
