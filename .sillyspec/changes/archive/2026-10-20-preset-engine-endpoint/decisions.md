# 决策记录（Decisions）— 2026-10-20-preset-engine-endpoint

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：最大风险：自动取消 Claude 勾选对「我就想同一条都勾上」的用户是强制收敛——但该组合保存后 Claude 与 Codex 必有一侧拿到错端点（今日三次实证），表单放行等于制造坏配置；notice 明示原因与出路（另建一条），属正确性优先。次风险：applyPreset 按当前勾选分派，用户先点预设后改勾选时形态可能与其预期不符——勾选联动会把形态拉回与勾选一致的状态，自愈。 试过但放弃的方案： - 预设拆成两条（OpenCode Go Codex 单列）：选择器条目翻倍且用户需自己判断选哪条，约束仍不可见；放弃。 - 保存时后端校验拦截坏组合（base_url 对勾选引擎不可达）：后端无法静态判定端点协议支持（需真实请求），动态探测成本高且时序不适配；放弃（表单联动前置收敛更便宜）。
