# 需求规格(Requirements)— PPM项目关联平台工作区

## 功能需求

- **FR-01**:系统支持 PPM 项目与平台工作区建立**多对多关联**(一个项目可关联多个工作区,一个工作区可关联多个项目)。
- **FR-02**:项目维护页可为项目**绑定/解绑工作区**,并查看已关联工作区列表(展示 name/status/type)。
- **FR-03**:工作区详情页可为工作区**绑定/解绑 PPM 项目**,并查看已关联项目列表(展示 project_name/project_status)。
- **FR-04**:同一 项目↔工作区 关联**不可重复绑定**(幂等,重复绑定返回 409 而非 500)。
- **FR-05**:**项目侧**绑定/解绑需 PPM 项目 **manager** 权限(复用 `data_scope`/`manager_project_ids`);**工作区侧**需**工作区成员**权限;越权返回 403。
- **FR-06**:关联列表查询**过滤软删除工作区**(`deleted_at IS NULL`),不展示已软删工作区。
- **FR-07**:删除 PPM 项目或硬删工作区时,关联记录**级联删除**(CASCADE),不留孤儿。
- **FR-08**:**未关联**的项目/工作区,行为与现状完全一致(零破坏)。
- **FR-09**:绑定前校验目标项目/工作区存在(不存在返回 404,而非 FK 报错)。

## 非功能需求

- **NFR-01**:兼容 PostgreSQL(生产 asyncpg)与 SQLite(单测 aiosqlite),无方言专属语法。
- **NFR-02**:migration 遵循 chain 规范(唯一 revision id + `down_revision` 接当前真实 head,部署前 `alembic heads` 单头)。
- **NFR-03**:PPM 已上线模块**零回归**(ppm 全量测试通过)。
- **NFR-04**:跨平台兼容(Windows/Linux/macOS)。
- **NFR-05**:OpenAPI 类型重新生成后前端类型对齐(`pnpm gen:types`)。

## 验收标准(关键 AC)

- AC-1:项目页能绑定 2 个工作区、解绑 1 个,列表正确反映;工作区页对称操作,数据与项目页一致(同一张表)。
- AC-2:非 manager 用户在项目侧绑定被拒(403);非工作区成员在工作区侧绑定被拒(403)。
- AC-3:重复绑定同一对返回 409。
- AC-4:软删除的工作区不出现在项目的关联列表里。
- AC-5:删除一个项目,其在所有工作区的关联记录同步消失(CASCADE)。
- AC-6:PPM 原有功能(增删改查/导出/成员管理)无回归。
