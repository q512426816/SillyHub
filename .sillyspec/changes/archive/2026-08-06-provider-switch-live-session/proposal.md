# 提案书(Proposal)

## 动机
切换默认供应商后,运行中的交互式会话仍锁在创建时的供应商凭证上,不生效。用户必须重开会话才能用新供应商,违背直觉、打断工作流。

## 关键问题
1. **凭证烧死**:LLM 凭证在 lease claim 时一次性烧进 claude 子进程 env,之后不重读——旧会话无法感知默认供应商变更。
2. **切换脱节**:`set/unset_default` 只改 DB 的 `is_default`,不通知任何运行中进程——切换与运行中会话完全脱节。
3. **停止不一致**:停止供应商后旧会话仍用已停止的平台凭证,而非回退本机——状态不一致。

## 变更范围
默认供应商变更(set 启动 / unset 停止)后,后端校验凭证 → 查 active 会话 → WS 推送变更 → daemon 在 turn 边界用新凭证重启 claude 子进程并 resume 对话历史。覆盖后端 + daemon + 前端三端。

## 不在范围内(Non-Goals)
- 不做会话级独立选供应商(仍跟随用户默认)
- 不处理 batch task run(独立 lease,不受影响)
- 不做历史已结束会话的回溯切换
- 不改 lease 生命周期 / claim 机制 / 表结构
- 不解决宿主机本机也未配凭证的善后(停止后本机无凭证 → 子进程报未登录属预期)

## 成功标准(可验证)
- 未切换供应商时,所有行为与现状逐字一致(brownfield 零回归)
- 启动新供应商后,运行中会话在当前回复完成后用新供应商,对话历史完整保留
- 停止供应商后,运行中会话回退本机 claude 凭证
- 切换不中断当前生成中的回复
- 新供应商凭证无效时,运行中会话保持原供应商,前端提示错误
