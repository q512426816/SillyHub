## 实页确认（用户下次打开即验收，预期形态）

在 `http://127.0.0.1:3000/workspaces/<wid>/changes/<cid>`（或部署域名）打开任一变更：

1. **页头**：面包屑（变更列表 / 变更 key）→ 标题 + 状态胶囊（在途=阶段名「进行中」/ 归档=「已归档（+轻量变更）」）→ Key/类型/位置/影响/描述单行截断；操作区右侧 = 删除（权限可见时）+ 继续执行（归档态不出）。
2. **阶段条常驻**于 tab 栏之上；点击某阶段 → 自动切到「过程」tab 并在时间线上只显示该阶段（清筛选 chip 可恢复）。
3. **四 tab**：概览（默认）/ 产出 / 过程 / 文件与对账。归档变更只有前三枚（「文件与对账」隐藏），且地址栏带 `?tab=files` 时自动回到概览。
4. **概览**：左主区 = 待办卡（有待办时）→ 变更摘要四格（当前阶段/任务进度/已用时长/最后信号）→ 最近动态倒序 5 条 → 末行「最后信号」；右信息栏 = 基本信息 / 执行用量（7 项，在途有「按模型明细」）/ 会话（最近 3 条 + 工作台入口）/ 范围对账计数 / 产出速览。归档态：摘要变成果四格 + 归档留档统计摘要 + 最终动态，用量区标题为「执行用量（合计）」且无明细入口。
5. **产出**：顶部知识图谱独立分区（画布高 420px + 右侧节点详情栏 + 层级 1/2/3 跳 chips），其下六组资产（每组最多直接显示 5 行，超出给「展开全部 N 条」）；在途态不出现「归档留档」组；图谱/资产取数失败时分区保留并给明确文案（不再整区消失）。
6. **过程**：一条统一时间线（行带来源胶囊「步骤/事件/锚点」+ 阶段胶囊 + 提交短哈希；行可展开看输出全文；卡头阶段 chips 与上方阶段条联动）+ 任务进度清单（☑/☐ + 推断时刻「≈」+ 提交锚，断链时显示「时刻不可推断（观测断链）」）+ 阶段跨度统计。
7. **文件与对账**：变更文件树直接内嵌（左树右预览/ diff）+ 范围对账卡（三态计数/分仓/明细弹窗/本地命令）+ 关联的快速任务。

**找东西验证（R-03 发现性探针，请用户实际翻一遍）**：①切 tab 是否一眼看出每区放什么；②归档态是否直觉地少了「文件与对账」；③把 `?tab=assets` 贴进地址栏刷新，是否停在产出；④在概览「最近动态」与过程「全量时间线」之间切换是否顺手。若有不顺手处，回 feedback 即可（tab 划分与首屏取舍是本变更的主设计面，调整成本低）。

## 与设计的有意偏差（执行期裁决，均落 decisions.md）

- **D-017**：归档留档「保底渲染」由「以自身取数呈现可用部分」收窄为「分区在场 + 明示不可用 + 可重试 + 指路变更文件」（0 端点约束下 patch 摘要与主查询同源）；资产卡新增可选 `archived` prop 使首帧失败也能判定归档语义。
- **D-018**：归档概览的「归档留档」渲染为统计摘要 + 指路「产出 · 归档留档」，文件清单与单文件 diff 入口只在产出 tab 出现一次。

两项偏差均属**降级文案与挂载位置**层面，不改变任何数据来源与业务语义；用户可在验收时否决并要求恢复原文口径。
