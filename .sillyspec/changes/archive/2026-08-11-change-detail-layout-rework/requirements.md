# 需求规格（Requirements）

## 角色

| 角色 | 说明 |
|---|---|
| 变更操作者 | 在变更中心推进/审核/调试 SillySpec 流程的用户（本变更主要使用者，非专业代码背景，需界面自解释） |

## 功能需求

### FR-01: 左主右辅布局
覆盖决策：D-001@v1
Given 用户打开任一变更详情页（桌面宽屏 ≥1024px）
When 页面渲染完成
Then 主体为两栏：左侧主线区（当前阶段操作 + 智能体执行日志），右侧 320px 次线侧栏（变更文件/会话调试/审核历史/任务看板）

### FR-01b: 移动端单列折叠
覆盖决策：D-001@v1
Given 视口宽度 <1024px
When 页面渲染
Then 退化为单列：主线在上，次线卡片以可折叠形态堆叠在主线下方

### FR-02: 会话与执行日志分离
覆盖决策：D-002@v1
Given 详情页已加载
When 用户查看主线区
Then 只见「智能体执行日志」（流程自动 run），不见「会话」；「会话调试」出现在次线侧栏

### FR-03: 审核历史读真实数据
覆盖决策：D-003@v1
Given 某变更存在审核记录（`change.stages.review_history` 非空）
When 用户展开次线「审核历史」卡
Then 按时间倒序显示每条审核的中文标签/颜色/意见/时间，不再是「暂无审查记录」

### FR-03b: 审核历史兼容异构形状
覆盖决策：D-003@v1
Given `review_history` 数组同时含 gate 形状（`{decision,submitted_at,...}`）与 rerun 形状（`{action,stage,comment,at}`）
When 渲染审核历史
Then 两种形状均正确归一化显示（gate→按 decision 映射，rerun→「重跑 {stage}」），不报错、不漏条

### FR-04: 删除旧区块
覆盖决策：D-003@v1
Given 详情页已加载
When 渲染完成
Then 不再出现「审批状态」区块；「审查记录」旧实现（读 listReviews 死表）被「审核历史」取代

### FR-05: 智能体入口收敛
覆盖决策：D-004@v1
Given 详情页已加载且当前阶段有待办操作
When 用户查看主线「当前阶段操作区」
Then 推进/审核/触发智能体/运行验证门禁/Agent 供应商·模型/团队开关集中在该区内，页面其它位置无重复入口

### FR-05b: 子步骤进度不重复暴露入口
覆盖决策：D-004@v1
Given 主线「智能体执行日志」内含子步骤进度（SillySpecStepProgress）
When 渲染
Then 其内嵌「触发智能体/执行下一步」按钮不渲染（组合时传 `onDispatch=undefined`），避免与操作区双入口

### FR-06: 组件化与死代码清除
覆盖决策：D-004@v1
Given 本变更完成
When 查看代码结构
Then page.tsx 瘦身为编排层；7 个区块组件位于 `components/changes/detail/` 并各有测试；`handleExecute`/`handleTransition` 死代码已删除

## 非功能需求

- **兼容性**：纯前端重组，不改 API/表结构/业务语义；未启用新功能时可用操作集合与现状一致。
- **可回退**：改动集中前端单页+新组件目录，回退 = revert 前端提交，无数据迁移、无后端依赖。
- **可测试**：每个新组件独立 vitest；现有测试（team-toggle 迁移、session-section）回归通过。
- **旧数据兜底**：`review_history` 缺省/为空显示「暂无审核历史」；字段缺失宽容兜底不崩。
- **组件库一致**：沿用本页 `@/components/ui`，不引入 antd。
