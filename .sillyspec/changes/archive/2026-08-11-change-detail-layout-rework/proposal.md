# 提案书（Proposal）

## 动机

变更中心详情页是 SillySpec 流程的主操作台，但经多次需求叠加后信息架构混乱：用户反馈「会话和智能体日志感觉重叠」「审查记录和任务进度显示乱七八糟」「看不懂审查记录是什么」。本变更重做该页展示结构，让页面聚焦「现在该干嘛」，次要信息收侧栏，并救活永远空白的「审查记录」。

## 关键问题

1. **「审查记录」是僵尸区块**：它读的后端 `change_reviews` 表已无任何写入路径（真实审核历史改写在 `change.stages.review_history`，前端却没读），对任何新变更永远显示「暂无审查记录」，用户自然看不懂。
2. **「会话」与「智能体执行日志」概念重叠**：两者都是聊天/日志样式且紧邻，一个是流程自动跑的流水账、一个是用户主动发起的对话，混在一起分不清。
3. **「进度」维度爆炸 + 入口分散**：阶段条/子步骤/团队/任务完成度四处「进度」并排；推进/审核/触发/门禁/模型等智能体操作入口散在 5+ 处，还有 `handleExecute`/`handleTransition` 两段死代码。

## 变更范围

重做变更详情页（`changes/[cid]/page.tsx`）展示结构：
- 布局改左主右辅两栏：主线（阶段操作区 + 智能体执行日志）、次线 320px 侧栏（变更文件 / 会话调试 / 审核历史 / 任务看板）。
- 全量重写：新增 7 个组件（`components/changes/detail/`），page.tsx 瘦身为编排层，每组件配测试。
- 新增「审核历史」组件读真实 `stages.review_history`（兼容 gate/rerun 两种形状），删除「审批状态」区块与死代码。
- 收口：智能体操作入口统一进「当前阶段操作区」；进度按阶段→子步骤→任务分层。
- 移动端 <1024px 单列折叠。

## 不在范围内（显式清单）

- 不切换组件库（沿用本页 `@/components/ui`，不引入 antd）。
- 不改后端、不新增 API、不改 DTO（审核历史直接读现有 `ChangeRead.stages`）。
- 不删除后端 `ChangeReview` 表 / 旧 `listReviews` 端点（前端不再引用即可，后端清理另立）。
- 不改智能体执行/派发/审核的业务逻辑与语义。
- 不改被复用组件（`AgentRunPanel`/`ChangeFileTree`/`ChangeSessionSection`/`SillySpecStepProgress`/`TeamProgress`）的内部实现。

## 成功标准（可验证）

- 打开详情页默认只看到主线（阶段状态 + 当前该做的操作 + 执行日志），次要信息在右侧栏。
- 「审核历史」能显示真实审核留痕（时间/结果/意见），不再是永远空白；「审批状态」区块不再出现。
- 「会话调试」与「智能体执行日志」在布局上分离，不再混淆。
- 智能体操作入口集中在一处「当前阶段操作区」，无散落按钮、无死代码。
- 新组件各有测试且通过；现有 frontend 测试回归通过（team-toggle 测试迁移后仍断言契约）。
- 移动端 <1024px 单列折叠正常。
