# 提案书（Proposal）

## 动机
自定义技能当前是**平台全局共享**（D-010），所有用户看到同一份、AI 也加载全部；维护权限又卡在平台管理员。用户希望自定义技能是**个人资产**——每人独立维护、只看自己的、AI 只加载系统 + 自己的。

## 关键问题
1. **权限前后端不一致**：后端 custom-skills 端点用 `SETTINGS_ADMIN`，前端 `page.tsx` 用 `is_platform_admin`——有 settings:admin 但非 platform_admin 的人后端允许、前端看不到按钮。
2. **全局共享不符合个人工具语义**：A 建的技能 B 也能看到、AI 也会加载，混在一起；name 全局唯一导致不同用户不能建同名技能。
3. **权限过严**：只有平台管理员能维护，普通用户无法管理自己的技能。

## 变更范围
- 自定义技能改 **per-user 独立**（复用 created_by 作归属键 NOT NULL+CASCADE，name 改联合唯一）。
- 维护权限**放宽到所有登录用户**（CRUD 自己的，越权 404）。
- daemon/AI **按用户同步**（manifest/bundle 透传 user.id，只返回系统 + 自己的）。
- 前端**菜单 + 按钮放开**（所有登录用户可见）。
- 现有全局数据**清空重置**。

## 不在范围内（Non-Goals）
- 不做技能共享 / 转移 / owner 变更。
- 不改系统 sillyspec-* 技能（全局只读共享不变）。
- 不做 per-workspace 隔离（是 per-user）。
- 不做技能版本 / 历史 / 草稿 / 导入导出。

## 成功标准（可验证）
- 登录用户（非管理员）能在技能管理页新增/编辑/删除自己的技能。
- 用户 A 的自定义技能对用户 B 完全不可见（列表/详情/AI 同步都隔离）。
- 用户 A 建 name=x，用户 B 也能建 name=x（不报 409）。
- 越权改/删别人的技能 → 404。
- 每个用户的 AI/daemon 只加载系统 sillyspec-* + 自己的自定义技能。
- 系统 sillyspec-* 技能所有用户只读共享不变。
- 现有全局自定义技能数据被清空。
