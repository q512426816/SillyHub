# 提案书（Proposal）— 2026-10-10-task-wakeup-quiet-threshold

## 动机

任务原话转写：后台任务终态唤醒对秒级短任务也全套触发：空闲时插对话流、忙时进排队栏混排且占 5 条额度，实测会话 13 分钟被灌 18 条通知，全是子代理内部秒级搜索步骤（仅 Claude Code 引擎触发，pi 无后台模式零影响）。
成功标准：
- daemon 唤醒加最短时长门槛：任务实际运行不足 60 秒不注入唤醒（emit/落行/注销语义不变），elapsed_ms 缺失时用注册表 startedAt 兜底计算，两者都缺时保持原唤醒行为
- backend 排队满员检查不再把 [后台任务通知] 系统通知计入用户 5 条额度：队满时用户消息照常入队判断不受通知挤占，系统通知队满也不被丢弃（仍走既有同条合并）
- daemon 与 backend 各有针对性测试覆盖新行为，仅跑修改相关测试，全量留给 CI
- 孙任务不冒泡（缺可靠 SDK 信号需 spike）与排队栏前端分开展示（纯展示优化）本变更不做，留待后续
