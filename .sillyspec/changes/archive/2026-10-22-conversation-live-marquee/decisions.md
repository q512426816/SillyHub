# 决策记录（Decisions）— 2026-10-22-conversation-live-marquee

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：- 最大风险：流式高频更新导致派生/重渲染成本。缓解：派生 `useMemo` 只依赖 `segments` 引用，条目上限 200；滚动由单条 rAF 直接写 `transform`，不触发 React 每帧 state 更新；组件 `memo` 隔离。 - 交互风险：跑马灯持续动效可能干扰阅读。缓解：单行低矮、低调配色、`aria-live="off"` 不打扰读屏；终态立即消失；用户上滚使轮尾离开视口时 IntersectionObserver 自动停表。 - 视觉风险：窄屏下超长工具参数撑破。缓解：条目等宽 13rem + `truncate` + `min-w-0`，轨道容器 `overflow-hidden`，整行不产生横向滚动。 - 动画正确性风险：轨道内容变化（新增条目）时目标位置需重算，否则最新条可能停不进视口。缓解：`entries` 变化即重算 target，只向更负方向推进、不回滚；首次挂载直接定位到最新。 - 放弃方案：① 吸底悬浮（用户明确选择"运行中轮末尾"）；② 多行信息牌 / 竖向事件流（用户选择单行横向跑马灯）；③ 每条思考 delta 都入队（会刷屏，改为按段 id 就地去重）；④ 复用「进度」视图的完整时间线（信息密度过高，违背"不必看清"的目标）；⑤ 固定节奏逐条停留 + 循环回放（用户裁决改为连续流动、不循环、只流到最新）。
