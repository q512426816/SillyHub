# 提案（Proposal）— 个人中心头像替换

## 问题

个人中心（桌面 `/account`、移动 `/m/account`）没有头像功能：桌面页只有修改密码卡片，移动页头像是昵称首字占位。桌面顶栏用户区、群聊中用户成员位置、1:1 会话中自己的气泡同样只有首字占位。用户无法设置自己的形象标识，多人协作场景下辨识度差。

## 方案概述

平台用户头像接入既有的头像基础设施（与 agent / 群成员头像同一套体系）：

1. **存储**：`users.avatar` 新列（VARCHAR 512 nullable）存文件中心 URL（`/api/file/{id}`）；图片本体经现有文件中心上传端点（`owner_type="user_avatar"`）落 MinIO。
2. **写入口**：新端点 `PATCH /api/auth/me/avatar`（登录态自助，值=设置、空串=清除置 NULL、None=不改）。
3. **UI**：桌面/移动个人中心新增头像上传（复用 `GroupMemberAvatarUpload` 扩 `ownerType` prop）；移动端头像整块可点。
4. **展示**：个人中心、桌面顶栏、群聊用户成员（后端回落解析：群内自定义优先，空值回落平台头像）、1:1 会话自己气泡，共五处。

## 价值

- 满足用户在个人中心（含手机端）替换头像的直接需求；
- 五处展示点统一形象，群聊多人场景辨识度提升；
- 全程复用已验证的管线（文件中心/useAvatarSrc/上传控件），零新基础设施，维护成本低。

## 备选方案（已否决）

- **独立公开头像服务**：无鉴权直链 + 独立存储路径。否决——隐私面扩大（未登录可见）、与文件中心并行两套体系、工作量大收益小。
- **base64 存数据库**：否决——DB 膨胀、接口响应放大、无缓存策略。

## 不在范围内（Non-Goals）

- PPM 个人工作台 `avatar_text` 维持首字（D-003，已上线模块不动）；
- 图片裁剪器、外链 URL 手输、群内用户成员独立头像覆盖 UI；
- 头像压缩/审核/尺寸限制专项；
- sillyhub-daemon（Node 守护进程）零改动。

## 规模与风险

scale=large（跨后端 auth/daemon-group 两模块 + DB 迁移 + 前端 7 文件 + 5 展示点）。主风险 R-03：群成员构造点的回落解析改动（已定位 `daemon/group` 模块三个构造点并给出批量预取方案）。
