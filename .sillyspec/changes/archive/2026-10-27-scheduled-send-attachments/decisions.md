# 决策记录（Decisions）— 2026-10-27-scheduled-send-attachments

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：- 最大风险：**附件 chips 残留或误清的观感回归**——清理时机若用全清（clear）会误伤用户在创建窗口期新上传的附件。缓解：按本次携带 id 精确过滤（onSendSettled 同款 `prev.filter`），meta 镜像逐 id delete；新增测试断言「部分删除后只清剩余」。 - 次要风险：空文本+附件定时属行为放宽，用户可能误建无上下文的定时消息——后端既有附件豁免口径（D-7 看图说话）已覆盖该形态的合法性，与普通发送/忙轮排队一致，不额外设限。 - 试过放弃的方案：①定时弹窗内做独立附件上传入口——上传管线与 UI 重复建设，且与既有交互叙事冲突（弹窗说明「请先在输入框写好要发送的内容」，入口语义是「把输入框现有内容定时发出去」），放弃；②只修 page 模式——dialog 模式同缺口，双模式必须同修否则口径分裂（两处 confirmSchedCreate 历史上就是成对复制维护）。
