# 提案书（Proposal）— 2026-10-27-scheduled-send-attachments

## 动机

任务原话转写：用户反馈定时消息发送后 agent 收不到附件。排查确认：后端定时消息全链路（schema/落库/到点派发重放）均支持 attachment_ids，缺口在前端——会话面板 dialog/page 两模式 confirmSchedCreate 创建定时消息时只传 prompt+dispatch_at，不传附件 id，且创建成功后附件 chips 残留输入框（用户误以为已随消息发出）。排队消息与立即发送（引导注入）链路前后端附件完整，不动。

成功标准：
- 会话面板 dialog 与 page 两模式创建定时消息时，输入框已上传附件的 id 随请求体 attachment_ids 携带
- 定时消息创建成功后，输入框附件 chips 与附件元数据镜像同步清空（与文本草稿清空同口径）
- 定时发送弹窗在携带附件时展示附件预览列表，让用户可见附件将随消息发送
- 带附件时允许空文本创建定时消息（对齐普通发送 D-7 看图说话口径），空文本且无附件仍禁用确认
- 更新/新增前端测试覆盖定时创建携带附件断言，相关测试与 lint 通过
