# 决策记录（Decisions）— 2026-10-12-run-level-change-attribution

## D-001@v1: 风险与死路（design 槽4 收割）
- 类型：process
- 状态：confirmed
- 答案：最大风险：口径双轨期混乱——存量会话（如用户 10-10~10-12 那条 665 轮会话）轮上无锚，仍按会话链接全量摊派，与新会话的拆分口径并存。缓解：FR-03 显式冻结存量行为（防回归用例钉死）；仓库规则 11 允许重置开发数据，用户可选择重跑。 试过但放弃： - 复用 `AgentSession.change_id` 作可变上下文——该列语义是「会话创建时绑定的变更」（派发链写入、会话列表展示消费），拿它当游标会混淆两个含义，且派发会话 change_id 不应被后续命令覆盖；弃。 - submit 时回溯打锚（把 run.change_id 按当轮出现的命令改写）——会把整轮摊给轮中才出现的命令，归属误差方向更差；弃。 - 平台会话水位表（照抄本地机制）——需消息序回放与水位修剪，复杂度高；轮级打锚同效且复用既有原子单位；弃。 已知口径缝隙（评审 P3 披露，范围外不违约）：@ 联想绑定通道（`daemon/session/service/helpers.py` 落 change_session_links）只落 link 不回写 `current_change_id`——经 @ 绑定的变更收不到带锚轮，其统计按旧口径走链接认领（偏小非双计，不会错归别的变更）。本变更上下文回写仅覆盖 run_sync 命令解析通道（run/flow 两命令族）；@ 通道跟进留待后续变更。
