# 设计文档（Design）— daemon 版本可见与构建号自动注入

## 1. 背景

daemon 在 register/heartbeat 已上报两个版本字段：`DAEMON_VERSION`（`package.json` 语义版本，0.1.0）+ `BUILD_ID`（git short sha + 时间戳，由 `src/build-id.ts` 提供）。backend 在 `daemon_instances.version/build_id` 存储（`runtime/service.py:194-195, 220-221, 349-352`）。

两个问题：

1. **版本不可见**：`GET /api/daemon/runtimes` 等 6 个 runtime 端点（list / read / update / disable / enable / offline）service 查询漏 JOIN `daemon_instances`、router 没 `_runtime_read` 填充，导致 DTO `daemon_version/daemon_build_id` 恒 null（`router.py:946` + `service.py:415-422`）。仅 machines（机器级聚合）端点 JOIN 正常。前端 C-002 已把版本上提机器头（走 machines），故前端能看到版本；但 `/api/daemon/runtimes` 端点契约不一致，daemon 自检等调用方仍 null。
2. **构建号 dev rebuild 不变**：`BUILD_ID` 由 `src/build-id.ts` 提供，当前硬编码 `4c238ebe-20260729112052`。仅 `pnpm bundle`（`build-bundle.sh:29-39`）重写它；`pnpm build`（tsc，开发编译）不更新。故本地开发 rebuild 构建号恒定，用户"改了 daemon 版本也不变"。

## 2. 设计目标

- **FR-01**：修复 backend 6 个 runtime 端点 JOIN，让 `daemon_version/daemon_build_id` 在所有 runtime 读端点一致可见（不止 machines）。
- **FR-02**：让 `BUILD_ID` 在每次 `pnpm build`（tsc）时自动重新生成（git short sha + 时间戳），dev rebuild 立即见效；`pnpm bundle` 与 `pnpm build` 共享同一生成脚本（源头单一）。
- **FR-03**：`build-id.ts` 移出版控，避免每次 build 脏污 git 工作区；`postinstall`/`prebuild` 自动生成，保证 clone/CI 后 tsc 不缺文件。

## 3. 非目标（Non-Goals）

- 不改 daemon 上报逻辑（`hub-client.ts` 已正确上报 `DAEMON_VERSION` + `BUILD_ID`）。
- 不改语义版本 0.1.0（`package.json`，手动管理大版本里程碑）。
- 不改前端 `/runtimes` 页面（C-002 已用 machines 端点显示版本 + 构建号短码）。
- 不改 daemon 生命周期（register/heartbeat/session/lease/state 均不变）。

## 4. 拆分判断

不拆分，单变更完成。改动跨 sillyhub-daemon + backend 两端但逻辑高度内聚（都围绕"daemon 版本可见 + 唯一标识"），无独立可交付的子模块。不走批量模式（非模板×数据）。

## 5. 总体方案

### A. daemon 构建号 build 自动注入（sillyhub-daemon，对应 FR-02 / FR-03）

1. **新增 `scripts/gen-build-id.mjs`**（node ESM，跨平台）：
   - `git rev-parse --short=8 HEAD`（`child_process.spawnSync`，失败 / 非 git 目录 fallback sha 为 `"unknown"`，最终 `BUILD_ID="unknown-<ts>"`，仍带时间戳可区分多次 build）
   - 当前时间戳 `yyyymmddhhmmss`（node `Date`，脚本独立运行可用）
   - 拼 `${sha}-${ts}`，写 `src/build-id.ts`：`// AUTO-GENERATED by gen-build-id.mjs — do not edit\nexport const BUILD_ID = "${id}";\n`（**无 `: string` 注解** —— backend 正则 `\s*` 不吃冒号，带注解会破坏 self-update 提取，见 R-04）
2. **`src/build-id.ts` 移出 git 版控**：加入 `.gitignore`，`git rm --cached`；文件保留为构建产物。
3. **`package.json` scripts**：
   - `"prebuild": "node scripts/gen-build-id.mjs"`（`pnpm build` 前自动跑）
   - `"build": "tsc"`（prebuild 自动先跑）
   - `"postinstall": "node scripts/gen-build-id.mjs"`（clone/CI install 后生成默认 `build-id.ts`，避免 tsc 缺文件）
   - `"bundle": "bash scripts/build-bundle.sh"`（内部 `:29-39` printf 逻辑改为调用 `gen-build-id.mjs`，源头单一）
4. **daemon 上报不变**（`hub-client.ts:337-338` register / `:365` heartbeat 已上报 `BUILD_ID`）。

**效果**：每次 `pnpm build` 重新生成 `BUILD_ID`（git sha + 时间），dev rebuild 立即见效；bundle 同源；git 工作区干净。

### B. backend 6 个 runtime 端点 JOIN 修复（backend/app/modules/daemon，对应 FR-01）

1. **`runtime/service.py`**：`list_runtimes()`（`:415-422`）+ 单 runtime 读/改的 service 查询加 `JOIN DaemonInstance`（`select(DaemonRuntime).outerjoin(DaemonInstance, DaemonRuntime.daemon_instance_id == DaemonInstance.id)`），返回 runtime 时一并带出 instance（或返回 `(runtime, instance)` 结构，具体在 plan 阶段定）。
2. **`router.py`**：6 个端点（list `:934-946` / 单读 `:567` / update `:817` / disable `:834` / enable `:851` / offline `:885`）调 `_runtime_read(runtime, owner, instance)`（复用 `:442-463` 模式）填充 `daemon_version/daemon_build_id`。
3. **测试**：新增/调整 runtime list 测试，断言 register 后 `GET /api/daemon/runtimes` 返回 `daemon_version != null`。

## 7. 接口定义

无新增 API。改动是既有端点内部 JOIN + 既有字段填充：

- `GET /api/daemon/runtimes` 响应 `DaemonRuntimeRead.daemon_version/daemon_build_id`（`schema.py:189-190`，字段已有）从 `None` → 实际值。
- `gen-build-id.mjs` 输出 `build-id.ts`：`export const BUILD_ID: string = "<sha>-<yyyymmddhhmmss>";`（类型签名不变，仅值变）。

## 7.5 生命周期契约

**不涉及生命周期契约**（lifecycle contract: N/A）：本变更不改动 daemon 的 register / heartbeat / session / lease / agent_run / state_transition 任一事件。仅 ① 既有 register/heartbeat 已上报的版本字段在 backend 读端被正确 JOIN 出来；② 构建号在 build 时重新生成。无新事件、无状态变化。

## 8. 数据模型

不改 schema。复用既有字段：

- `DaemonInstance.version`（`model.py:64-67`，daemon 语义版本）
- `DaemonInstance.build_id`（`model.py:71-74`，git short sha）
- `DaemonRuntimeRead.daemon_version/daemon_build_id`（`schema.py:189-190`，JOIN 带出）

JOIN 路径：`DaemonRuntime.daemon_instance_id → DaemonInstance.id`。

## 9. 兼容策略

- 项目未上线，不要求历史兼容（CLAUDE.md 规则 11）。
- 旧 daemon（不上报 `daemon_version/daemon_build_id`）：register body 字段 Optional（`schema.py:131-132`），`instance.version/build_id` 为 NULL，`_runtime_read` 已处理 `instance=None`（返回 None），行为不变。
- `build-id.ts` 移出版控后：`postinstall` + `prebuild` 双保险生成默认值，旧 clone 首次 install 即生成，tsc 不缺文件。
- 不改变的 API / 表结构：所有端点路径、DTO 字段、表 schema 不变。

## 10. 风险登记

| 编号 | 风险 | 等级 | 应对策略 |
|---|---|---|---|
| R-01 | `gen-build-id.mjs` 在非 git 目录（npm global install）失败 | P2 | fallback `BUILD_ID="unknown-<ts>"`，保证 tsc 不挂；bundle 分发版 build 时已注入，运行时不依赖 git |
| R-02 | `build-id.ts` 移出版控后，开发者本地 tsc 找不到文件 | P1 | `postinstall` + `prebuild` 双保险生成；CI install 自动跑 |
| R-03 | backend JOIN 增加查询开销 | P2 | `DaemonRuntime.daemon_instance_id` 已有 FK 索引，outerjoin 单级，开销可忽略；`list_runtimes_page` 已有同模式 |
| R-04 | `gen-build-id.mjs` 格式破坏 backend 提取版本的正则 | P1 | `latest.json` 的 version 实为 backend 运行时从 bundle JS 正则提取（`_compute_daemon_version` `router.py:110-125`），非 build-bundle.sh 直接产；正则 `BUILD_ID\s*=\s*["']([^"']+)` 的 `\s*` **不吃冒号** → gen 输出必须用无注解格式 `export const BUILD_ID = "<id>";`（不带 `: string`），否则 self-update 链路断。execute task-01 已据此定稿；task-05/11 回归测试断言该正则能提取 |
