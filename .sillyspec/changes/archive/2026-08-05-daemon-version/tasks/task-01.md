provides:
  contract: BUILD_ID
  format: "<git-short-sha-8>-<yyyymmddhhmmss>"
  fallback: "unknown-<yyyymmddhhmmss>"
  output_file: sillyhub-daemon/src/build-id.ts
  output_signature: "export const BUILD_ID: string = \"<id>\";"
goal: >
  新增 node ESM 脚本 scripts/gen-build-id.mjs，跨平台（Win/Linux/Mac）生成
  BUILD_ID（git short sha 8 位 + yyyymmddhhmmss 时间戳），写入 src/build-id.ts；
  非 git 目录或 git 命令失败时 fallback 为 unknown-<ts>，保证 tsc/postinstall 不挂。
  此脚本作为 build 与 bundle 的共享源头（D-002），供 task-02~06/11 消费。
implementation:
  - 用 child_process.spawnSync 调 git rev-parse --short=8 HEAD 取 8 位 short sha；非 git 目录或非零退出码时 sha 置 unknown（不抛错）
  - 用 node Date 拼时间戳 yyyymmddhhmmss（padStart 补零，本地时间），最终 BUILD_ID 为 sha-短横-ts 拼接
  - 用 node fs.writeFileSync 写 src/build-id.ts，首行 AUTO-GENERATED by gen-build-id.mjs — do not edit 注释，次行 export const BUILD_ID 带双引号与 string 类型注解（与 daemon-version.ts 风格一致，兼容 backend 正则 BUILD_ID\s*=\s*[\"']）
  - 输出文件路径相对脚本所在目录解析（path.resolve(import.meta.dirname, ../src/build-id.ts)），不依赖 cwd
  - 控制台打印生成结果 BUILD_ID=<值>，便于 CI 日志追溯
acceptance:
  - sillyhub-daemon/scripts/gen-build-id.mjs 存在且为 node ESM（package.json type 已 module，无需扩展名配置）
  - 在 sillyhub-daemon 目录跑 node scripts/gen-build-id.mjs 后，src/build-id.ts 内容为 AUTO-GENERATED 注释加 export const BUILD_ID 字符串字面量
  - BUILD_ID 形如 abc12345-20260804111415（sha 8 位 + 时间戳 14 位），git sha 缺失时为 unknown-20260804111415
  - Windows（git bash / cmd）/Linux/macOS 均能运行，不依赖 bash 仅用 node 内置模块
  - git 命令失败不抛异常，脚本始终退出码 0
verify:
  - 手动 node scripts/gen-build-id.mjs 后 cat src/build-id.ts 校验格式
  - 在非 git 临时目录复制脚本运行，断言输出 unknown 前缀且退出码 0
  - 用正则 BUILD_ID\s*=\s*[\"']([^\"']+) 模拟 backend _compute_daemon_version 提取，确认能拿到值（守护 self-update 链路 R-04）
constraints:
  - 不改 src/build-id.ts 内容本身（该文件的写动作归本脚本，版控移出归 task-02）
  - 不改 package.json scripts（接线归 task-03）
  - 不改 build-bundle.sh（替换 printf 归 task-04）
  - 仅用 node >=20 内置模块（fs/path/child_process/url），不引入新依赖
  - 输出双引号字符串，匹配 backend 提取正则容忍 string 类型注解
