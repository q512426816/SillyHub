# 设计记录（Design Record）— 2026-10-27-mobile-chat-dense

## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

用户真机复验反馈会话页 agent 回复要「占满一行、字体和间隔小点、显更多内容」——第三轮密度回调（16px 放大→14px→13px）。只改 `frontend/src/app/globals.css` 的 `[data-variant="mobile"]` 排版块（ql-20260915-009 建立的元素级调版通道）：气泡 .turn-bubble max-width 94%→100%、正文 markdown 14px/1.7→13px/1.6、气泡行高 24→21px、标题降一档（h1/h2 16→15、h3/h4 14→13、code 13→12.5，全部守住 12px 紧凑档下限）、时间线滚动区 padding 12→8px。选此方案因为它沿既有选择器隔离机制：该属性只挂 /m/ 会话页 SessionPanel 根，PC 宿主零命中（用户本轮再次强调「只有手机端！PC 端不要影响到」）。

## 接口契约

动了哪些函数/端点/命令/文件格式？对外可见的签名或行为变化是什么（含「无」的说明）？

无——纯 CSS 数值变更（零函数/端点/命令/文件格式改动）；对外可见变化仅手机端会话页排版（气泡满宽、字号行高收紧）。类名、DOM 结构、组件 props 全部不动。

4. 作用域：跨工作区/跨仓/多实例时数据会不会串台？

1. 乱序/迟到到达：不适用——纯静态 CSS，无输入/事件序问题。
2. 并发写：不适用——单文件静态样式，无运行时数据写入；git 层面冲突风险极低（该块近期无并行改动方）。
3. 切换/生命周期：不适用——样式常驻，会话切换/中断不产生状态。
4. 作用域：data-variant="mobile" 只由 /m/ 会话页根携带——desktop 会话页/dialog/悬浮宿主 DOM 无该属性，规则零命中不串台；多实例（多标签页）各挂各的属性互不影响。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

最大风险：13px 若仍偏大/偏小需再调——参数集中在该块一处，回调成本一行。放弃的方案：改组件内 Tailwind 类（需在各组件加 mobile 分支 prop，改动面 5+ 文件）——CSS 数值变更走既有元素级通道一处收口更稳；下调至 12px 紧凑档底线——用户仅说「小点」，13px 相对 14px 保守回调一档，避免一步到底过小再回调。
