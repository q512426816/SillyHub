# 决策记录（Decisions）— 2026-10-22-askuser-dock-inputbar

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：最大风险：pending 期间输入框不可用——用户想「先不答、先输入别的内容」没有入口。缓解：卡头最小化按钮保留，最小化后右下角胶囊可还原；pill 定位还原保留；且 pending permission 语义上本就阻塞 agent 轮次（先答后问语义），输入框被替换与队列语义一致。此边界为用户显式裁决（「替换底部的用户输入框（遮挡）」）。 次风险：SessionInputBar 重挂载丢内部局部态（光标/展开的菜单）——受控值全在父级，丢的只是瞬时 UI 态，可接受。放弃的方案：a) absolute 定位把卡覆盖在输入栏上（输入框仍挂载）——「遮挡」会露出输入栏残边、且输入栏仍可聚焦与「答题优先」语义矛盾，弃；b) 全部最小化时恢复输入框（需最小化状态上抛或受控化）——状态同步面增大、交互分叉（输入框出现/消失多一层条件），且「pending 期间不该发新消息」语义下价值低，弃；c) 保留 TurnTimeline 内渲染不动、仅用 CSS 把卡定位到输入区——跨组件定位（卡在滚动容器内、目标在容器外）需 hack（fixed/portal），脆弱，弃。
