# 需求（Requirements）— 会话消息排队体验修复与增强

## 用户故事

1. **US-1**：作为用户，我排队的一条消息失败后，后面的消息不应永远卡在"等待中"——
   系统应自动继续派发后面的消息（瞬态失败），我也应能对"等待中"的消息手动触发
   立即发送（滞留兜底）。
2. **US-2**：作为用户，daemon 短暂掉线期间我的排队消息不应被批量打成"发送失败"；
   恢复后它们应继续正常派发。
3. **US-3**：作为用户，队列变化（派发/删除/他人操作）应在聊天界面即时反映，而不是
   等最多 5 秒。
4. **US-4**：作为用户，我可以拖拽调整排队消息的先后顺序。
5. **US-5**：作为用户，正在运行的这轮回答没说完时，我可以对某条排队消息点
   "立即发送"——打断当前轮，立刻把这条发给 AI（语义经用户确认）。
6. **US-6**：作为用户，我可以重新编辑排队消息的文字（改错字/改措辞），失败的消息
   编辑后自动回到等待中。
7. **US-7**：作为用户，我可以一键复制聊天记录里任何一条消息（我的提问、AI 的回答、
   思考过程展开的正文）。

## 功能需求

对应 design.md FR-01~FR-07（滞留修复/非 active 收敛/SSE 实时/拖拽排序/立即发送/
重新编辑/复制按钮）。

## 非功能需求

- 排队串行不变式（单会话至多一个活跃 run）与排队上限 5 不变。
- 所有新操作走会话行锁，与既有派发/入队互斥。
- daemon（sillyhub-daemon）零改动、零发版。
- 前端零新增依赖。

## 验收标准（摘要）

- A1 队头瞬态失败后下一条自动派发；连续 2 次失败停止并不再连环转 failed。
- A2 会话 reconnecting/suspended 时排队保持等待中；recover 回 active 后自动续派。
- A3 queue_changed 事件驱动队列 UI 即时刷新。
- A4 拖拽换位后顺序落库（刷新页面不丢），派发按新顺序执行。
- A5 立即发送：空闲=当场发出；忙碌=打断当前轮后该条最先发出。
- A6 编辑保存生效；failed→等待中并尝试派发。
- A7 三类气泡 hover 出复制按钮，复制内容为纯文本（用户消息剥离附件标记）。
