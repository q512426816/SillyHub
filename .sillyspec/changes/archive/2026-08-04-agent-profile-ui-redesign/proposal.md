# 提案书（Proposal）

> 变更 `2026-08-04-agent-profile-ui-redesign` · 方案 A（稳进版）
> 前置:`2026-08-02-agent-profile-layer`(AgentProfile 配置层 + 后端 CRUD)已 archive。

## 动机

智能体档案(AgentProfile)的后端与数据层已于 2026-08-02 完整落地,但前端体验未跟上,被业务方判定为「拉跨」。档案本应是高频复用的「智能体人设模板」,却因入口深、展示差、填表顺、缺功能而被冷落。本提案在不改后端契约的前提下,重做档案的前端体验,让这套配置层真正可用起来。

## 关键问题（现有方案为何不够）

1. **入口太深**:档案管理入口藏在工作区详情页的快捷入口里(`workspaces/[id]/page.tsx:361`),用户要先选工作区→进详情→找入口,层级深,不符合「高频复用模板」的定位。
2. **表格不适合人设展示**:当前 9 列 antd DataTable(序号/名称/供应商模型/工具策略/MCP/技能/可见范围/版本/操作),MCP 与技能列堆 tag,一眼抓不到「这个档案是谁、能干啥」。「人设模板」用表格行展示是信息架构错配。
3. **表单填着不顺、无反馈**:640px Modal 平铺 8 字段,新手不知每项意义,填写无即时反馈,看不到填完长啥样。
4. **缺功能**:无搜索、无按工作区/可见范围/供应商筛选、无「预览人设下发效果」。

## 变更范围

本次做（6 Phase）:
- **P1** 后端新增只读聚合端点 `GET /api/agent-profiles?scope=mine`(跨工作区并集,带 workspace 归属)
- **P2** 前端数据层加聚合 fetch + hook;`gen:types` 同步
- **P3** 共享卡片墙组件(角色卡 + 搜索筛选条 + 网格)
- **P4** 带实时预览的重做表单(宽弹窗左填右预览 + 全局页工作区上下文选择器)
- **P5** 全局页路由 `/agent-profiles` + 侧边栏一级菜单 + 工作区详情页入口保留 + 人设预览弹窗
- **P6** 任务页选档下拉视觉对齐 + 回归校验

## 不在范围内（显式清单）

- 不改后端 AgentProfile CRUD 契约(只加只读聚合端点)
- 不改三级 visibility 鉴权、系统预置只读、profile=None 兜底链
- 不改 daemon-entity-binding / spec 注入管线 / lease 生命周期
- 不重做任务页选档下拉逻辑(仅视觉对齐)
- 不做暗色模式 / 移动端 / 档案市场 / 跨工作区活共享 / 配额计费
- 不动 `build_spec_bundle` 渲染管线(人设预览纯前端只读)

## 成功标准（可验证）

1. 侧边栏「智能体」分组出现「智能体档案」一级菜单,点击直达 `/agent-profiles`(经 menu-permissions.ts + permission.ts:41 空 perms 可见)。
2. 全局页展示当前用户可见的全部档案(个人 + 各工作区 + 平台 + 系统预置),按工作区/可见范围/供应商筛选生效。
3. 越权防护:actor A 看不到 actor B 的 private 档、看不到非成员工作区的 workspace 级档(测试覆盖)。
4. 新建/编辑为宽弹窗左填右实时预览,8 字段齐全;全局页新建首字段「工作区上下文」选定后能力区有数据。
5. 系统预置档案卡显示「只读」,无编辑/删除。
6. `GET /api/agent-profiles`(无 scope)行为不变,`?scope=mine` 返回聚合集。
7. `pnpm gen:types` 同步,`tsc --noEmit` + `eslint` 0 error,前端测试通过。
