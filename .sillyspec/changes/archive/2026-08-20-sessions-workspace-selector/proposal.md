# 提案书（Proposal）

## 动机

`/sessions`（智能体会话总入口）新建会话时不支持选择工作区，导致 agent 只能以"裸会话"模式运行——跑在空默认目录，看不到项目代码，读不到 SillySpec 规范文档。只有通过「工作区会话页」或「变更中心」发起的会话才有完整项目上下文。

用户需要在统一入口（`/sessions`）内直接选择工作区，一步到位获得代码访问 + SillySpec 规范上下文，减少跳转成本。

## 关键问题

1. **裸会话无用场景多**：agent 不知道你在做什么项目，回答需要反复口述上下文，效率低。
2. **统一入口体验断层**：`/sessions` 号称"跨工作区统一会话入口"，但实际新建的会话无法挂任何工作区，功能名不副实。
3. **既有安全缺口随 UI 开放显性化**：后端 `create_session` 收到 `workspace_id` 不校验归属，原来是内部工作区会话页隐式限定成员用户，`/sessions` 开放选择器后任何用户可任意传工作区 ID 用他人项目目录，需顺手补上。

## 变更范围

本次做：
- `/sessions` 新建会话表单新增「工作区」选择器（可选，默认不使用），选中后提交 `workspace_id`，复用后端已有链路获得完整工作区上下文（cwd + SillySpec 拉取 + 回灌）
- 选工作区时自动联动选中该工作区绑定的机器，可手动换
- 后端 `create_session` 补 workspace 归属校验（404 无权限/不存在）

## 不在范围内（Non-Goals）

- 不改会话执行链路（后端已支持 workspace_id，只补入口和校验）
- 不改工作区会话页（`/workspaces/{id}/sessions`）和变更中心会话——它们已有工作区上下文
- 不做强制锁定机器（用户选择保留灵活性）
- 不做工作区搜索式下拉（超 100 个工作区场景）
- 不做多成员项目路径分别解析

## 成功标准（可验证）

- 不选工作区时提交行为与改前逐字节一致（`workspace_id` 不出现在请求体）✅
- 选工作区后 AgentSession 创建带正确 workspace_id，agent cwd = 该工作区项目根目录 ✅
- 选工作区后表单顶部出现绿色提示条，内容准确显示工作区名 ✅
- 选工作区时机器选择器自动选中绑定机器（若在线）✅
- 传入无权限的 workspace_id → 后端返回 404，无任何数据落库 ✅
- 新增测试覆盖所有分支 ✅
