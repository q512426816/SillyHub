# 提案书（Proposal）

## 动机
知识搜索（2026-10-15-platform-knowledge-search）的向量索引是进程内存态：重启后首查需全量重嵌实测 304.67s（6586 chunks/437 文件），且该代价随语料增长线性恶化。用户裁决持久化到 PostgreSQL pgvector：重启零重建、增长曲线稳定（KNN 毫秒级不随量级退化）、数据可查可运维。

## 关键问题
1. **重启重算**：内存索引服务一重启就清空，5 分钟级首查不可接受（R-01 遗留移交项）。
2. **增量同步复杂度**：文档天天变（归档/蒸馏都写 spec 树），库内向量需跟随增删改——任何持久化方案共有，需最小化实现。
3. **测试环境无 vector 类型**：测试跑 SQLite 内存库（backend/conftest.py:248），pgvector 算子不可用，需方言分叉。

## 变更范围
- backend：search.py 检索层改造（内存索引 → DB 查询 + 差量同步）+ 新 ORM 两表 + alembic 迁移（CREATE EXTENSION vector + 建表）+ pyproject 加 pgvector 依赖 + 测试适配。
- deploy：postgres 镜像换 pgvector/pgvector:pg16（生产+dev compose）+ 升级步骤说明。
- **零改动**：API 端点/api-types/前端/daemon（D-005 对外契约冻结）。

## 不在范围内（显式清单）
- 不做启动预热/后台常驻同步协程（随 D-010 落选；查询路径内联同步已覆盖）。
