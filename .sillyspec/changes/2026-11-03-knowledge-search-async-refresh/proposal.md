# 提案书（Proposal）

## 动机

知识搜索的懒同步（切块+嵌入）内联在搜索请求里，生产实证（2026-11-03 诊断）工作区变更后首搜 63-81 秒阻塞，期间用户只见等待提示；历史上叠加 worker OOM 打断同步。用户已拍板 A1 路线（decisions.md D-001）：读路径彻底去嵌入化，同步后台化，搜索立即返回存量索引结果（stale-while-revalidate）。

## 关键问题

1. 搜索响应时间与嵌入计算耦合：任何语料变更后的首搜都要在请求内等差量/全量嵌入（数十秒起，随语料增长恶化）。
2. 同步失败（如 worker OOM 被杀）导致该次请求异常或降级，且下次搜索从头再来——用户视角「每次都在建索引」。
3. 结果新鲜度对前端不可见：响应无法区分「索引即最新」与「存量索引+后台同步中」。

## 变更范围

- backend `search_sync` 读路径去嵌入化：指纹判定（fresh/stale/missing）+ 后台同步调度（进程内 asyncio task + 在途注册表强引用，D-005）+ 即时返回存量索引或词面降级结果。
- 响应契约增可选字段 `index_sync`（fresh/scheduled/building，D-004）；router 透传。
- 前端 `lib/knowledge.ts` 透传 + 知识页搜索框下方轻提示文案行。
- 测试面适配：既有 35 用例改「显式 drain 后台任务」模式 + 新增调度/去重/失败清理/禁建零调度用例。

## 不在范围内（显式清单）

- 不做 daemon 事件预建端点（A2 路线，D-001 落选）。
- 不改检索打分/融合口径、切块与指纹算法、`knowledge_search_chunks/state` 表结构（零 schema 迁移）。
- 不引入跨进程任务队列、持久化任务表、定时重试（D-003：懒触发自愈）。
- 不做查询向量预热（R-06 接受冷启 1-2s 留在响应路径）。
- 不动 `server_build=False`（禁建库）语义（逐字不变，仅加回归锁用例）。

## 成功标准（可验证）

- 指纹失配时搜索请求路径零嵌入调用（fake embedder 计数断言），响应即时返回存量索引结果且 `index_sync="scheduled"`；后台任务 drain 后二次搜索返回全语义结果。
- 无索引工作区首搜即时返回词面降级结果且 `index_sync="building"`，请求路径零落库；后台 drain 后建库完成。
- 并发两次失配搜索仅调度一个后台任务（注册表判重断言）。
- 后台任务异常后注册表清理、可再次触发（无残留锁死）。
- `server_build=False` 全流程零调度零写库（既有用例回归锁通过）。
- knowledge 域既有+新增测试全绿；前端 typecheck/lint 通过。
