# 提案书（Proposal）

## 动机

会话门户是用户与平台 Agent 协作的主入口，但左侧会话树缺乏基本的管理能力（置顶、重命名），聊天侧也缺少「延后触发」的发送手段。本变更补齐这两块，让高频会话触手可及、让「过段时间再继续」类指令不依赖人守在页面前。

## 关键问题

1. **排序单一**：会话树只有「最近活跃」一种排序（`coalesce(last_active_at, created_at) DESC`），高频会话一旦沉底就要滚动寻找；工具上报类会话（本地 Agent）多且活跃，进一步挤压人工会话的位置。
2. **标题不可控**：会话标题由服务端从首条 user_input 派生前 30 字（`title` 列 NULL 时回退），派生结果常常截断或语义不明，用户没有修正入口。
3. **没有定时触达手段**：用户常有「1 小时后让它继续」「明早 9 点跑个回归」的需求，现状只能到点手动发送；页面关闭后没有任何机制能替用户触发。

## 变更范围

- `AgentSession` 加 `pinned_at` 列 + 置顶/取消置顶/重命名三端点（照 archive 先例：行锁、幂等、SSE 多端同步）+ 列表排序置顶优先（分组内置顶语义）。
- 新表 `agent_session_scheduled_messages` + 定时消息 CRUD 三端点 + 到点派发常驻协程（sweeper，照 sweep.py 模式，复用 `inject_session_as_service`，忙轮自动进既有消息队列）。
- 前端：会话树行 hover 操作加置顶/重命名（行内编辑）；聊天输入栏定时按钮 + 定时弹窗 + 定时消息列表条（可取消）；`pnpm gen:types` 同步类型。

## 不在范围内（显式清单）

- 不做周期性/重复定时（每天/每周）——仅一次性（D-002@v1）。
- 不做全局置顶（跨工作区置顶到树顶）——仅分组内置顶（D-002@v1）。
- 不做定时消息编辑（改内容/改时间）——只支持取消后重建。
- 不做群聊（group chat）行的置顶/重命名——仅普通 chat 会话行。
- 不改 sillyhub-daemon——定时派发复用 backend→daemon 既有 SESSION_INJECT 通道。
- 不做 daemon 侧任何逻辑改动。

## 成功标准（可验证）

- 未置顶、无定时消息时，会话列表行为与现状完全一致（排序、响应结构仅增 `pinned_at` 字段）。
- 置顶会话出现在其工作区分组最前，多端（多标签）经 SSE 秒级同步置顶/重命名结果。
- 重命名后列表标题立即更新且优先于自动派生标题。
- 定时消息在页面关闭、backend 重启后仍按时派发（落库 + sweeper ≤30s 补发窗口）。
- 到点派发四分支行为正确：空闲→直接发出；忙轮→进既有队列；终态/软删→failed(session_inactive)；队列满→failed(queue_full)。
- backend 新增测试（pin/rename、scheduled CRUD、sweeper 四分支）全绿；既有 daemon/agent 模块测试零回归；前端 `tsc` 干净、session-list-panel 既有测试零回归、新行为有测试。
