# 需求规格（Requirements）

## 角色
| 角色 | 说明 |
|---|---|
| 会话用户 | 在智能体会话（单聊/群聊）输入区上传附件并发送消息的最终用户 |
| 智能体（agent） | 消息接收方，读取正文（含行内附件引用）与附件清单 |

## 功能需求

### FR-01: 右击待发附件在正文末尾插入引用标签
Given 会话输入区存在至少一个已上传未发送的附件 chip
When 用户右击（contextmenu）该 chip
Then 光标在输入框内时插入到**光标当前位置**，否则插入到正文**末尾**（D-006@v2）；插入后输入框**自动聚焦**、光标落标签尾，可继续输入；浏览器默认右键菜单不弹出；同一附件允许多次右击插入多个引用

### FR-02: 同名附件引用唯一化
Given 已存在引用标签的附件名与本次右击的附件同名
When 插入新引用
Then 新引用自动加序号后缀（`【文件名·2】`、`【文件名·3】`…），保证正文内每个引用标签文本指代唯一附件；删除任一附件不改变其它（同名）附件已插入引用的文本

### FR-03: 编辑态引用标签的渲染与删除
Given 正文含引用标签
Then 输入框镜像高亮层将其渲染为标签样式（品牌色底、圆角、右上角 × 角标）；点 × 角标删除该处一次出现；退格键在光标贴标签尾部且无选区时**一次删除整个标签**（非逐字，D-004@v2 用户反馈），标签中部或普通文本退格仍逐字；既有输入行为（打字/IME/@联想/粘贴上传/高度拖拽/草稿持久化）零回归

### FR-04: 发送置换为 uuid 锚定正式引用
Given 正文含引用标签且用户发送消息
When 发送组装 prompt
Then 每个可解析的编辑态 token 置换为 `[附件引用:<uuid>|<文件名>]`（uuid 与随消息附件、头部标记行对齐，同名附件可精确区分）；无法解析的孤儿 token 原样保留；置换后输入框与附件 chips 按现状清空；后端 API/存储零变更；全部发送路径（含定时发送）覆盖

### FR-05: 删除附件联动清空正文引用
Given 正文含某附件的引用标签
When 用户点该附件 chip 的 X 删除
Then 正文内该附件的全部引用标签同步移除，其它附件的引用不受影响

### FR-06: 历史消息引用标签渲染与点击预览
Given 历史消息正文含 `[附件引用:<uuid>|<文件名>]`
When 气泡正文渲染
Then 引用渲染为标签节点（蓝色主气泡内用白色半透明色调保证可读，D-005@v2），点击打开 FilePreviewModal 按 uuid 在线预览附件内容（与已发送附件 chips 同链路）；解析失败片段原样显示文本；本变更前的历史消息渲染逐字不变

## 非功能需求
- 兼容性：Windows/Linux/macOS 桌面浏览器；未插入引用时行为与现状完全一致（零回归回退路径）
- 后端零改动：不新增/修改任何 API、schema、存储格式
- 移动端触屏无右键，本期不做长按替代（显式边界，记 R-05）
