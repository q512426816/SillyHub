# 需求规格（Requirements）— 2026-10-23-marquee-thinking-fulltext

## 功能需求

### FR-01: thinking 条目的文本不再按 64 字截断，保留折叠空白后的完整思考内容

- thinking 段映射为跑马灯条目时**必须**只做空白归一（多行/连续空白折叠为单空格），**禁止**按 64 字截断。
- 其他类型条目（工具/子代理/文件/警告等）的摘要截断规则**必须**保持不变。
- 文本内容**禁止**被改写或省略（不得丢字）。

#### 场景：长思考

- Given 一条 thinking 段文本长度 500 字
- When 派生跑马灯条目
- Then 条目 text 为完整 500 字（仅折叠空白），不是 64 字摘要

#### 场景：工具条目

- Given 一条工具段主参数很长
- When 派生条目
- Then 仍按既有摘要长度截断（不受本次影响）

### FR-02: 运行中的思考条目按文本长度自适应滚动时长，保持约 21 字每秒的稳定速度，全文依次流过

> 2026-10-23 用户裁决修订：不再循环滚动。运行中从开头一次滚到**当前最新末尾**；
> 思考仍在流式增长时，滚动终点随文本延伸并继续跟随，不得停在旧末尾；
> 思考完成后停止滚动并**回到开头**截断展示（+耗时）。以下为现行口径。

- 运行中文本**必须**从开头向末尾单向滚动，**禁止**复制内容循环回放。
- 流式增长时终点**必须**随文本延伸并继续滚动，**禁止**停在旧末尾。
- 落后距离越大滚动**SHOULD**越快（约 220~900px/s），避免追不上流式输出。
- 思考完成（status 变为 done）后**必须**停止滚动、回到开头单份截断显示，并显示耗时。
- 图标、转圈、耗时区**禁止**参与滚动。

#### 场景：流式增长跟随

- Given 思考正在流式增长，滚动已接近旧末尾
- When 新文本到达、文本变长
- Then 重新计算终点并继续滚动到新的最后一个字符，不停在旧位置

#### 场景：思考完成

- Given 思考段从 running 变为 done
- When 条目重新渲染
- Then 停止滚动，回到开头截断显示并显示耗时，不循环

### FR-03: 完成态仍显示截断文本与耗时；其他类型条目的摘要截断规则不变

- 条目完成后**必须**停止滚动、单份截断显示、显示耗时；不得因全文保留而把长文本铺开。
- 其他类型条目的既有行为**必须**不回归。

#### 场景：思考完成

- Given 长思考段变为完成态
- When 渲染条目
- Then 单行截断 + 耗时，不滚动

### FR-04: 现有测试更新并通过，新增全文与滚动时长断言；lint 与 typecheck 通过

- **必须**新增：长 thinking 全文不截断、ticker 时长随文本长度变化（长文本 >3s、短文本 3s）。
- 现有 24 个用例**必须**全部通过；lint / typecheck **必须**通过。

#### 场景：回归核验

- Given 完成实现
- When 运行测试与 lint
- Then 全部通过

### FR-05: 原型中的长思考文本可看到完整内容流动展示

- 原型页**必须**包含长思考文本（≥200 字），运行中可看到全文依次流动。
- 原型验证**必须**确认条目 text 长度大于 64、ticker 时长大于 3s。

#### 场景：原型核验

- Given 打开原型并让长思考处于运行中
- When 观察条目
- Then 完整思考内容依次流过，不是单行 64 字摘要
