部分 1：incident（故障）状态机加「合法转换校验」

现在的漏洞：改状态时只做「值合法」检查，不查「能不能这么跳」。导致任意两个状态都能互跳，甚至已经解决(resolved)的故障能被改回待处理(open)还残留解决时间/解决人 —— 终态可复活，数据失真。

规则 1（终态只能重开）：已解决(resolved)只允许改回排查中(investigating)重新查，不能退回待处理/已缓解。
规则 2（重开清字段）：从 resolved 重开时，自动清空 resolved_at（解决时间）和 resolved_by（解决人），避免「已解决但还挂着旧解决记录」的脏数据。
规则 3（非法跳转报错）：任何不在上表 ✓ 里的跳转，接口返回 422 并提示「当前状态 → 目标状态 不支持」+ 列出允许的目标；值本身非法（如 unknown）仍返回 400。
规则 4（同状态幂等）：把状态改成它当前就是的值（如 open→open）不校验、直接放行（不报错）。
对现有功能的影响：已逐一核对现有测试/页面，只用了 open→investigating 和 open→resolved 两种跳法，都在允许范围内 —— 现有功能零影响、现有测试不用改。

部分 2：SSRF 三连（堵住「让后端去访问内网/本机」的三个口子）

SSRF 是什么：攻击者让后端服务器替它去请求一个地址。如果后端不校验这个地址，攻击者就能借后端的身份访问内网服务、本机(127.0.0.1)、云元数据(169.254.169.254，可偷云密钥)，甚至读服务器本地文件。本次统一建一个安全入口 app/core/ssrf.py，三个出站点都过它。
① MCP Webhook 回调
注册 webhook 时 + 每次投递前，都校验回调 URL。
✗ 拒绝：127.0.0.1、169.254.169.254、10.x/192.168.x 等内网、file://
✓ 放行：公网 http/https 地址
② Worktree git clone
克隆仓库前校验 repo_url 的协议（不查 IP，允许内网 git 服务器）。
✗ 拒绝：ext::（可远程执行命令）、file://（读本地文件）、裸路径
✓ 放行：https、ssh、git 协议、git@host:path 简写
③ http_get 工具
发请求时逐跳校验，且每次跳转(重定向)后重新校验。
✗ 拒绝：IPv6 私网(::1/fc00::)、跳转到 127.0.0.1 等
✓ 放行：公网地址；重定向最多跟 3 跳、每跳都查
