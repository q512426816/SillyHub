# 提案书（Proposal）

## 动机

变更详情页（`frontend/src/app/(dashboard)/workspaces/[id]/changes/[cid]/page.tsx`）是平台使用频率最高的页面之一，也是当前「信息最乱」的页面。用户原话：「我想重新设计下变更详情页面，现在显示太乱，而且感觉不够直观清晰」。近两个月该页已被增量补丁多次（2026-08-11 定「左主右辅」、2026-09-26 primer 化、2026-09-28 批次调整、2026-10-15 主栏重排 + 步骤时间线默认收起），但每次都在既定骨架上继续加卡，结构问题从未被处理。

## 关键问题

1. **两条时间线讲同一件事**：`ChangeStepTimeline`（数据源 `change.steps`）与 `ChangeTimelineCard`（数据源 `GET /changes/{cid}/timeline`）都在展示「时间戳 + 任务名 + 完成状态」，只是分组方式与附带字段略有不同；用户要来回对照两处才能拼出完整过程。
2. **页面不管变更走到哪一步都长一样**：归档的变更照样渲染「执行中」类空态，在途的变更照样挂着「归档留档」的空位；范围对账卡无论有没有意义都常驻侧栏（778 行）。
3. **单卡过载**：沉淀资产卡 861 行，内含 8 个分组（每组固定高度、组内独立滚动）+ 一张知识图谱画布 + 4 个弹窗；同一张卡里字号 6 档、徽标色系 5 套，认知负担高。
4. **首屏三行弱信息前置**：进页面先看到「阶段条 → 最后信号 → 执行用量」三行全宽内容，真正需要用户操作的审批卡被推到第三屏之下。

## 变更范围

- 页面骨架改为**顶部四 tab**（概览 / 产出 / 过程 / 文件与对账），tab 状态写入 URL（`?tab=`）；页头改用 primer `PageHead`，阶段条常驻于 tab 栏之上。
- 页面内容按**变更状态自适应**：在途首屏 = 待办 + 进度摘要 + 最近动态；归档首屏 = 成果总结 + 归档留档 + 最终动态，且 tab 集收窄（隐藏「文件与对账」）。
- **两条时间线合并为一条统一时间线**（新纯函数负责合并口径），任务面由独立「任务进度」清单承载。
- **知识图谱独立成区**（原嵌在沉淀资产卡内）；**范围对账下沉**到「文件与对账」tab；**执行用量与会话入口**压缩进概览右侧信息栏。
- 资产分组由「固定高度 + 组内滚动」改为「自然高度 + 最多 5 行 + 展开全部」；变更文件树改为在 tab 内直接内嵌（不再以弹窗为唯一入口）。
- 实现路径按**原型驱动**：原型已产出（`prototype-change-detail-v2.html`，prototype-as-code 真码产物）并通过用户批准，实现按「接线」规程执行（fixture 换真实 hooks，结构对不齐停机裁决）。
- 与本次冲突的 **6 条活需求显式取代并落盘**（逐条标 superseded 并指向承接 FR）。

## 不在范围内（显式清单）

- 不做移动端详情页改造（`frontend/src/app/m/workspaces/[id]/changes/[cid]/page.tsx` 不动）；但移动端复用的组件符号与行为契约 MUST 保持可用。
- 不做后端改动：不新增/修改端点、DTO、响应体，不涉 `pnpm gen:types`（两条时间线在前端无损合并）。
- 不改变业务语义：审批（`submitStageReview`）、派发、verify 门禁、scope-audit 计算、知识图谱查询端点全部原样复用。
- 不替换组件库：继续 primer（结构组件）+ 既有 `@/components/ui` 原子件，不引入 antd 新组件。
- 不做 tab 内嵌套 tab 或二级折叠迷宫（面板内最多一级分组）。
- 不改变更列表页（`frontend/src/app/(dashboard)/workspaces/[id]/changes/page.tsx`）。
- 不删除被移动端或测试面引用的旧组件文件（`change-step-timeline.tsx` / `change-timeline-card.tsx` 仅从桌面页卸载）。

## 成功标准（可验证）

- 打开任一在途变更详情页，首屏 MUST 只呈现「概览」tab（阶段条 + 待办（有则显）+ 摘要 + 最近动态），不再出现全宽的执行用量卡与两条并列时间线。
- 打开任一已归档变更详情页，tab 集 MUST 为三个（概览/产出/过程），MUST NOT 出现「文件与对账」tab，且 MUST NOT 出现在途空态文案；在途页 MUST NOT 出现「归档留档」占位。
- 切换 tab MUST 更新 URL `?tab=`；直接访问带 `?tab=assets` 的链接、刷新页面，MUST 停在「产出」tab；非法 `?tab=` 值 MUST 回落「概览」。
- 过程 tab MUST 只出现一条时间线；同一源内重复条目 MUST 只出现一次；tasks 域的 task-done 事件 MUST NOT 单独成行（由任务清单承载，其勾选时刻显示为推断值）。
- 「产出」tab 的知识图谱 MUST 位于资产清单之外（独立分区，画布高度不再受 280px 卡片内嵌约束）；图谱不可用/失败 MUST 呈现显式空态说明而非整区静默塌陷。
- 资产分组 MUST 为自然高度且每组最多直接显示 5 行，超出 MUST 提供「展开全部 N 条」；MUST NOT 出现组内独立滚动区。
- 「文件与对账」tab MUST 直接渲染文件树（左树 + 右预览），MUST NOT 仅提供「打开」按钮再套弹窗。
- 移动端详情页的既有测试 MUST 全绿；桌面页 10s 轮询与终态停轮、删除入口、审批四种分支与通知降级文案、范围对账三态与降级指路、四个弹窗机制 MUST 行为不变。
- 原型与最终实现结构 MUST 一致（对不齐处 MUST 带截图裁决并留痕，MUST NOT 静默降级）。
