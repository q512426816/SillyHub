# 提案书（Proposal）— 2026-10-30-askuser-config-pending

## 动机

任务原话转写：会话页面 askuser 弹窗（待答问题）时，保留最下面那块配置条（供应商/模型/档案/思考等级）可操作；点击提交回答后按新选项继续执行、没改配置则不打断继续；改动的地方高亮显示「待生效」——不仅 askuser 场景，正常会话也高亮，让用户知道目前改动了什么选择还没生效。

预调研结论：暂存**能力**已全量交付（2026-10-25-session-config-deferred-switch + 2026-10-26-config-staged-all-states）——askuser 待答期间与运行中，四控件点选均仅本地暂存、零网络请求零新轮次，随下一条消息发送一并生效；提交回答后 AI 同轮回喂 SDK 无缝继续（daemon permission.ts:623）。真正的缺口是**感知层**：暂存完全静默（D-001 静默决策），控件只显示新值，无「已记住待生效」标记，用户无法确认改动被记住；且暂存为面板内存 state，刷新页面即丢。

用户四项裁决（step3/step5）：①生效时机=随下一条消息生效（不选「答复即写入」的协议扩展）；②高亮=仅逐控件标记（无常驻汇总行，生效语义走悬停提示），标记形态=brand 描边+浅底（首轮的「待生效」文字角标被裁决去掉）；③范围=仅主会话页面（page 模式），dialog 弹窗面板不补配置条；④刷新丢失=顺带解决（sessionStorage 按会话隔离短期持久化）。

## 成功标准（可验证）

- 有暂存的控件（staged 字段存在）渲染 brand 描边+浅底高亮（无文字角标），悬停 title=「已记住，将随下一条消息发送时生效」；无暂存控件外观与现状一致
- 取消暂存（选回当前生效值）或发送成功后，对应控件高亮消失
- 暂存（含档案显示名）实时写入 sessionStorage（key 按会话 id 隔离）；刷新页面后恢复高亮与暂存值；发送成功/切换会话后清对应条目；关闭标签页自然清除
- 持久化数据损坏（JSON 解析失败/结构异常）静默丢弃回退空暂存，不报错
- 现有暂存行为（点选暂存/发送生效/忙轮排队/未挂 staged 调用面）零回归；相关单测更新并通过

## 不在范围内（Non-Goals）

- 不改 askuser 答复链路（respondSessionPermission / PERMISSION_RESPONSE / daemon 同轮回喂）——答复不携带配置、不触发即时切换（用户裁决方案 A）
- 不做「答复提交即无轮写入会话配置」的后端/daemon 无轮切换通道（2026-10-26 已评估放弃，本次维持）
- 不给 dialog 弹窗模式会话面板补配置条（范围仅 page 模式主会话页面）
- 不做 localStorage 跨标签页共享/TTL 清理（sessionStorage per-tab 已满足）
- 不做常驻「待生效」汇总说明行与文字角标（用户裁决：仅控件高亮本体+悬停）
- 不前置校验恢复暂存值的有效性（沿用发送失败保留重试语义）

## 变更范围

按成功标准机械推导，共 5 条验收面：
1. 逐控件待生效高亮渲染与消失（session-config-bar.tsx）
2. sessionStorage 持久化写入/恢复/清除（session-panel-page.tsx）
3. askuser 待答场景行为零改动（能力既有，本次仅补可视化）
4. 现有暂存链路零回归
5. 组件与面板测试更新通过
