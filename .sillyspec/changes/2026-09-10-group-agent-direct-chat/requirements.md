# 需求规范（Requirements）— 2026-09-10-group-agent-direct-chat

## FR-1 汇总收口模式

- FR-1.1 群级开关 `consensus_mode`（默认 False）开启后，一条消息 @ ≥2 个 agent 成员（含 @全体 展开）自动进入汇总模式；关闭时全链路与现状逐字节一致（D-002）。
- FR-1.2 汇总人选择：单 @ 命中首个（消息文本出现序）优先；纯 @全体 取 agent 成员表序（joined_at）首个；目标集 = 单 @ ∪ @全体展开去重（D-003）。
- FR-1.3 被咨询成员的意见不进群时间线，由后端在其回复轮终态后定向注入汇总人影子会话（busy 时中途注入 steering，409 竞态降级排队）。
- FR-1.4 收口触发：全员终态（delivered|failed|timeout）且 ≥1 delivered → 注入收口指令；或超时（`consensus_timeout_seconds`，默认 600、范围 60~3600）由后台循环强制收口，未响应成员在总结中如实标注（D-004）。
- FR-1.5 汇总人收口轮的 [[GROUP]] 段是本任务唯一进群出口；收口轮失败 → 状态卡标注 + 群内 system 兜底行，不允许群内死寂。
- FR-1.6 群里可见协调状态卡（谁在汇总 + 各成员已交/等待/失败/超时），过程细节在各成员影子会话时间线查看（D-006）；状态卡落库可回放。
- FR-1.7 边界：coordinator 触发失败 → 任务立即 aborted；收口注入前 coordinator 影子 ended/failed → aborted + 状态卡；群解散/删除 → open 任务静默 aborted；成员移除由超时兜底覆盖（design §12）。

## FR-2 agent 间私聊通道

- FR-2.1 互@触发的协作轮回复不进群时间线（投影层按 turn metadata 硬拦截，[[GROUP]] 标记也拦，不依赖 agent 自觉——D-007），定向注入发起方影子会话。
- FR-2.2 多轮往返：发起方收到私聊回复后可再 @ 对方继续讨论；防环护栏（链深度/同成员次数/滑窗限频、Redis fail-closed）沿用现有机制零改动。
- FR-2.3 协作轮内互@检测不早退（允许被咨询成员/汇总人在回复中 @ 其他成员发起私聊讨论）；shadow_direct 直聊轮早退语义保留。
- FR-2.4 私聊过程群内保留 typing 运行态提示，回复内容零泄漏进群。

## FR-3 可靠性与可观测（D-007/D-008）

- FR-3.1 汇总任务落库（唯一状态源），崩溃重启后未超时任务由收口钩子继续推进、超时任务被 sweeper 扫到——协调链不悬挂。
- FR-3.2 意见转交/收口指令均为后端注入的标准轮（turn_metadata 可审计），同 log_id 状态卡更新实时推送。
- FR-3.3 收口注入幂等：任务行锁 + status 状态机判定（closing/timeout 后不再注入）。

## FR-4 零回归

- FR-4.1 开关关闭时 send_group_message/投影/互@/直聊全链路行为与现状一致（回归底线）。
- FR-4.2 单聊（kind='chat'）/worker/quick-chat 会话零进入；daemon 侧零改动零新协议。

## 验收对照
