# 提案书（Proposal）— 变更中心冲突对比弹窗 + quick 条目 ql 编号展示

## 动机

变更中心「平台同步」处理区已能列出未决冲突并一键裁决（保本地/取平台），但用户裁决时**看不到双方内容差异**——面对 `quick-62e1d5fb` 这种看不懂的 ID 和 164~183 个冲突文件，只能盲选方向，选错就把新内容覆盖成旧内容。本变更让用户「先看差异、再做抉择」，并把 quick 条目标题换成用户能认的 ql 编号。

## 关键问题

1. **盲裁风险**：现有裁决确认弹窗只有文字后果描述，无内容对比。当前本机 3 条真实冲突各涉及上百个文件，方向选错代价高。
2. **ID 不可读**：quick 类冲突标题是 `quick-<hex8>` 会话 ID，用户无法关联到自己跑过的快速修复（ql 编号）。
3. **本地内容平台不可直读**：冲突的本地一侧内容只在 daemon 机器的 `.sillyspec/` 下，需要一条实时读取通道（复用 explorer RPC 先例）才能让对比发生。

## 变更范围

- daemon：新增 `sillyspec_conflict_snapshot` RPC（读本地冲突记录+文件内容/进度快照+ql_id+mtime）；心跳 pending_conflicts 补报 ql_id。
- backend：新增 compare 编排端点（并行取本地 RPC + 平台 spec 镜像/进度，difflib 服务端算 diff，四道截断护栏 + 双侧路径 containment 校验）；心跳 DTO 加 ql_id 可选字段；`pnpm gen:types` 同步类型。
- frontend：冲突行改造（ql 标题 + 发生时间 + 只留「查看对比」按钮）；新对比弹窗（时间条 + 文件清单/side-by-side diff / 进度关键信息对比表 + 底部裁决条）；工作区总览卡冲突清单同步 ql 标题。

## 不在范围内（显式清单）

- 不做逐文件分别裁决（裁决粒度仍为整个变更）。
- 不做冲突内容的心跳快照/缓存（每次查看实时拉取，机器离线不可看）。
- 不改外部 sillyspec CLI 源码、不改 09-04 已建的裁决通道与 ghost 清理。
- 不做二进制文件的内容级 diff（占位展示）。
- 存量两条 quick 冲突的 ql 编号回填（guard.json 已清理且无反查来源，兜底显示原 ID）。
