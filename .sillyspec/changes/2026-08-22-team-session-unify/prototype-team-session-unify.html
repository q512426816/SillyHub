会话内团队操作

核心心智：团队不是另一种会话，而是当前会话里 agent 的一种能力——就像子代理一样。你随时在对话里触发「派团队」，当前 agent 升级为主控（orchestrator），通过 MCP 工具派发分身（worker）：分身是真进程、可跨机器跨工作区，进度与结果直接回到这条消息流里，上下文不断、对话不换页面。不新增会话类型、不新增列表条目、没有独立团队页面。

01

普通会话 · 对话中途触发团队

一切发生在同一个普通会话里。前两轮是正常聊天；第三轮用户要动手了——点输入框旁的「派团队」按钮（或直接说“派个团队去做”），agent 作为主控拆解任务、经 MCP 派发分身。NEW 团队任务块（TeamTaskBlock）嵌在本轮消息流里：概要行常驻，展开见分身明细。你在团队干活期间照常追问、插队、改需求。

按钮、指令、自然语言最终都走同一条链路：给当前会话的 agent 注入团队 MCP 工具集（派分身/取结果/列分身/收敛/报进度），由它作为主控编排。按钮的价值是显式保证 + 范围配置入口；自然语言的价值是零操作成本。

04

链路与改动说明

核心洞察：现有 mission 链路的 MCP 基建（主控 5 工具、分身独立 worktree、跨工作区派发）全部保留——改的只是「主控从哪来」：不再是新建任务时另起一个一次性会话，而是把团队工具注入你正在聊的这个会话。

维度现状本方案
团队形态独立任务实体：另起主控会话 + 一次性烤死的指令，独立页面围观当前会话内的能力：agent 注入团队 MCP 工具即成主控，对话即指挥
触发只能从零创建一个任务；「用团队分析」按钮创建后与原会话断联会话中随时：按钮 / /team 指令 / 自然语言 / AskUser 选择，四路等价
沟通发起后无输入框；分身进度 10s 轮询整页控制台标准输入框 + 消息排队；分身进度嵌在消息流（任务块 + 进度段），追问实时转主控
上下文任务与发起会话无关（session_id 参数无人消费）主控就是你聊着的 agent，全程带对话上下文拆任务、汇总结论
项目跨工作区独立「项目团队会话」页面（仅项目经理）触发弹层里选项目范围 + Anchor，同一入口，无独立页面
保留的基建团队 MCP 5 工具与注入机制、分身 worktree 隔离、跨工作区派发、预算与收敛兜底、巡检——全部复用，不动
落地路径（评审通过后走 SillySpec 流程）
  1. 工具注入与会话绑定普通会话按需注入团队 MCP 工具（复用既有 isMainAgentSession 注入机制）；团队任务记录绑定发起会话，激活 mission.session_id 既有字段。
  2. 前端任务块新增 TeamTaskBlock 组件（violet 卡：概要 + 分身行 + 日志/产物入口）；进度视图新增分身段块与 MCP 工具卡渲染。
  3. 触发链路输入区「派团队」按钮 + 配置弹层（范围/项目/预算/分身预设）；/team 指令前缀；与自然语言触发统一到同一条后端链路。
  4. 收尾收敛结论回流消息流；删除独立 missions 页面、路由与菜单；「用团队分析」改为在当前会话直接触发；更新模块文档。
