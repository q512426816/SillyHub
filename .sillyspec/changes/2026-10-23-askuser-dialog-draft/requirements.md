# 需求说明（Requirements）— 2026-10-23-askuser-dialog-draft

## 背景与动机

会话页面 AskUser 工具弹窗（结构化问答卡 `AskUserDialogCard`，page / dialog / 群聊三宿主同款）有两处体验缺陷，由用户实测提出：

1. **选项与手动输入不互斥**：单选问题点了某个选项后，下方手动输入框仍可继续输入；输入了自定义文本后，选项按钮仍可点击勾选（`computeAnswer` 现为「输入优先覆盖选项」）。用户原话：「勾选的内容及输入的内容单选情况项应该是互斥的，目前勾选之后也能输入，输入之后还能勾选 不对」。
2. **未提交作答丢失**：用户已勾选的选项与已输入的自定义文本，仅存在于组件内存态（`useState`），刷新页面或切换会话后卡片重新出现但内容清空。用户原话：「用户选择的选项和输入的内容 刷新页面或切换会话后就丢失了（没提交的时候），这个也应该要保留的，参考 会话输入方案」。

用户已明确边界：**仅单选互斥**，多选保持现状（可勾多项，且可与手动输入合并作答）。

## 功能需求

### FR-01: 单选问题：选项勾选与手动输入互斥

单选（`multiSelect` 不为 true）问题，两种作答方式互斥，任一方向都不得同时可用：

- **场景 1（勾选后禁止输入）** Given 单选问题未作答，When 用户点击某个选项使其选中，Then 该问题的手动输入框变为禁用（`disabled`），用户无法再输入自定义文本，并显示「已选择选项，再点一次取消即可改为手动输入」类提示。
- **场景 2（输入后禁止勾选）** Given 单选问题手动输入框已填写非空白文本，Then 该问题所有选项按钮变为禁用不可点击，并显示「已填写自定义内容，清空后可选择选项」类提示。
- **场景 3（恢复可用）** Given 已选中某选项（输入框禁用），When 用户再次点击该选项取消选择，Then 输入框恢复可用且已有输入文本（若有）保留；Given 手动输入已被清空（trim 后为空），Then 选项按钮恢复可点击。
- 提交约束不变：单选答案仍为单值（选中项标签；或手动输入文本）。

### FR-02: 多选问题保持现状（回归锁定）

多选（`multiSelect === true`）问题行为不变：可同时勾选多个选项；手动输入框保持常驻可用。

- 多选问题**禁止**套用单选互斥的禁用逻辑（选项与输入框在任何勾选/输入组合下都必须保持可用）。
- 多选提交答案**必须**为「已勾选标签 ∪ 手动输入文本（trim 后非空才计入）」的并集，去重后上送。
- 本变更**不得**改动多选的渲染标记（`（可多选）`）与提交载荷形态（数组）。

### FR-03: 未提交作答跨刷新 / 跨会话切换保留

用户尚未提交的作答（每个问题的已选标签与手动输入文本）必须在页面刷新、切换会话（切走再切回）后原样恢复，参照会话输入框草稿的 localStorage 方案：

- **场景 1（刷新恢复）** Given 用户在单选问题选中「使用项目本地目录」并在另一问题手动输入了文本，When 页面刷新后该提问卡重新渲染（同一 `request_id`），Then 输入框内文本与各问题的选中项原样恢复，提交按钮可提交状态与刷新前一致。
- **场景 2（切换会话恢复）** Given 用户在会话 A 的提问卡填了作答未提交，When 切到会话 B 再切回会话 A（提问仍 pending），Then 作答内容原样恢复。
- **场景 3（隔离）** 不同 `request_id` 的提问卡作答互不影响（一个提问的草稿不得出现在另一个提问卡里）。
- 持久化失败（localStorage 不可用 / 数据损坏）降级为空作答，不崩溃。

### FR-04: 草稿清理不残留

- **场景 1（提交成功）** 提交成功后该提问的草稿立即清除。
- **场景 2（已答 409）** 提交撞「已被他人回答」409 时该提问的草稿清除（转已答关闭态）。
- **场景 3（孤儿兜底）** 提问已被回答 / 会话结束导致卡片不再出现时，其草稿由存活期上限（TTL）清理，不无限增长。
- **场景 4（不污染新提问）** 新提问使用新 `request_id`，不复用旧草稿（即使旧草稿尚未被 TTL 清理）。
- 提交成功与 409 already-resolved 两条路径**必须**立即调用清除，不得依赖 TTL 兜底（TTL 仅兜孤儿条目）。
- 草稿存活期**禁止**超过 7 天（过期条目在下次写入时被清理，避免 localStorage 无限增长）。

## 成功标准承接（原文逐字，来源 flow start --input）

- 单选问题：选中某个选项后手动输入框禁用不可输入；手动输入非空时选项按钮禁用不可勾选；取消选择/清空输入后另一侧恢复可用 → FR-01
- 多选问题保持现状：可勾多项，且可与手动输入合并作答（用户明确「仅单选互斥」）→ FR-02
- 未提交的单选项勾选、多选项勾选与手动输入文本，刷新页面或切换会话再回到该提问时原样恢复（参考会话输入草稿 localStorage 方案）→ FR-03
- 提交成功 / 被他人回答（409）/ 提问卡移除后该提问的草稿清除，不残留到下一次新提问 → FR-04
- tsc --noEmit 零错；ask-user 卡片与 pending-dialog-dock 相关测试全绿（新增互斥与持久化行为用例）→ 测试绑定四行 + 任务注册表 task-05
