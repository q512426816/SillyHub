# 提案书（Proposal）— SillyHub 侧边栏菜单信息架构重组

## 动机

SillyHub 侧边栏菜单当前"乱、功能藏、分组杂、视觉不统一"。核心痛点：「我的供应商」「技能管理」「MCP 管理」等功能在侧边栏看不到，必须先进「设置」翻找；菜单分组把凭证类与业务类混在一起；图标 emoji 与线条图标混用。本次重组菜单信息架构，让功能可直达、分组清晰、视觉统一。

## 关键问题

1. **功能埋藏且入口不一致**：供应商/技能/MCP 藏在设置页内（顶部卡片入口 + Tab），侧边栏无独立入口；而同类性质的 Git 身份/API 密钥已是侧边栏独立菜单——同一类功能，入口层级不一致，又乱又难找。
2. **分组语义混杂**：现状"管理"组把凭证类（Git 身份、API 密钥）与业务类（智能体控制台、Agent 团队、审批、审计）混在一组，缺乏功能域划分。
3. **视觉不统一**：菜单图标 emoji（menu-permissions.ts 的 icon 字段）与 lucide 线条图标（app-shell.tsx 的 MENU_ICON_MAP）混用，分组间距与高亮缺乏统一规范。

## 变更范围

- 侧边栏菜单按功能域重组为 5 组（工作区/智能体/配置中心/协作治理/系统管理），ppm 组隔离不变。
- 新增 3 个独立菜单：技能管理、MCP 管理（智能体组，平台级）、我的供应商（配置中心组）。
- 我的供应商新建独立页面 `/settings/providers` 直达；新增 `llm_provider:read` 权限控制可见性（角色管理可分配）。
- 设置页瘦身：移除 4 个卡片入口 + 供应商 Tab，保留工作区信息/智能体配置/安全策略/集成 4 个 Tab。
- 菜单视觉统一：lucide 图标、分组间距、高亮。
- 后端：`permissions.py` 新增 `llm_provider:read` 枚举（seed 启动自动同步，无需 migration）。

## 不在范围内（显式清单）

- 不改任何后端业务接口的鉴权逻辑（llm_provider/skills/mcp router 权限保持原样）。
- 不改 ppm 组菜单与隔离逻辑。
- 不改现有路由路径（仅新增 `/settings/providers`）。
- 不做"默认全员可见"的 migration 强制赋权。
- 不引入嵌套/多级菜单树（仍一层平铺）。
- 不改工作区级 skills/mcp 页面。

## 成功标准（可验证）

- 侧边栏按 5 组渲染，菜单项归属与 design §5.1 一致；ppm 组隔离不变。
- 我的供应商/技能管理/MCP 管理可从侧边栏直达对应页面。
- 我的供应商菜单对 platform admin 可见，普通成员经角色分配 `llm_provider:read` 后可见，未分配不可见。
- 设置页仅保留 4 个平台配置 Tab，无供应商 Tab、无卡片入口。
- 菜单图标统一为 lucide，无 emoji 残留。
- 前端受影响测试与后端权限测试全部通过。
