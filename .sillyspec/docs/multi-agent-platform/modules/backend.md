# 后端服务（backend）

## 定位

multi-agent-platform 的核心 API 服务，monorepo 的"大脑"。以 FastAPI 提供 REST/SSE/WebSocket 接口，承载多智能体协作平台全部领域逻辑：工作区管理、SillySpec 变更编排、Agent 运行时调度、PPM 项目管理、知识库、发布、权限治理等。是 frontend 与 sillyhub-daemon 的唯一数据后端，二者均通过 HTTP/WebSocket 调用它。

技术栈：Python 3.12+、FastAPI、SQLModel、Alembic（迁移）、PostgreSQL、Redis（缓存/会话）、httpx、uvicorn、uv（包管理）、pytest。代码组织为"核心 core + 按领域分 modules"两层结构。

- **会话 reopen/resume 链路加固**（2026-08-21-session-reopen-resume）：daemon 模块 `confirm-reconnected` / `mark-recovery-failed` 请求体 `SessionRuntimeRequest` 新增**可选 lease_id**——与会话当前挂起 lease 不匹配时幂等跳过（防陈旧确认误翻，DS-4），未提供保持现状向后兼容（旧 daemon 不受影响）；active→failed 翻转保留。**reopen 窗口语义**：reconnecting 且 `last_active_at` 超 `RECONNECTING_RETRY_WINDOW_SEC=180`（session/service.py）放行重开，旧挂起 lease 置 cancelled、新建 lease 重发 SESSION_RESUME；cwd 空拒绝时返回 409 中文文案（DaemonSessionNoCwd）。**lifespan 常驻巡检协程**：`session_reconnect_sweeper`（sweep.py，60s 周期，main.py lifespan 挂载）把 reconnecting 超时会话收敛 failed + 挂起 lease 置 cancelled，同时覆盖旧 daemon 不发 confirm 的过渡期。配套迁移 `20260821120000_backfill_session_agent_session_id` 回填 AgentSession.agent_session_id。

启动入口 `uvicorn app.main:app`，带 `lifespan` 钩子（初始化/释放 DB 引擎、Redis、遥测）。`app = FastAPI(...)` 实例在 `main.py` 构建，装配 CORS 中间件与全局异常处理器（`core/errors.register_exception_handlers`）。

## 关键逻辑

- **分层结构**：`app/core/`（config/db/redis/security/crypto/logging/telemetry/audit_hooks/spec_paths 等横切关注）+ `app/models/base.py`（SQLModel 基类）+ `app/modules/<域>/`（每域含 `router.py` + 业务/service + tests）。
- **领域模块清单**：admin、agent、archive、auth、change、change_writer、daemon、git_gateway、git_identity、git_log（2026-08-25-workspace-git-log）、health、incident、knowledge、ppm(5 子域)、platform_sync、release、runtime、scan_docs、settings、spec_profile、spec_workspace、task、tool_gateway、workflow、workspace、worktree。
- **Daemon 接入**：daemon 模块与 lease 模块共同支撑本地守护进程注册、领租约、心跳、消息回传的在线交互模型。**模型错误回传**：daemon 在 turn 失败时归类出 ModelError（auth_failed/quota_exceeded[不可重试]/rate_limited[可重试]/timeout/model_not_found/network/provider_error/unknown），经 notifyRunResult → close_interactive_run 三层透传（router+facade+实体）写 AgentRun.error_detail，run→failed。**run 终态翻会话终态补发 SESSION_END**（ql-20260823-006）：`close_interactive_run` 经 `_apply_session_terminal_status` 把会话翻 ended/failed 时（change 绑定会话每轮 run 终态都翻），commit 后经模块级 `_send_session_end_best_effort`（session/service.py，复用 `_resolve_daemon_id_for_runtime` 路由）best-effort 补发 SESSION_END 清理 daemon 内存 SessionStore 副本——此前只翻 DB 不通知 daemon，副本残留成僵尸，后续 reopen 全撞 SESSION_ALREADY_EXISTS 死循环（2026-08-23 bdec91a4 事故）；多轮对话保持 active 不发（防误杀活会话）。**孤儿 dialog 作废（ql-20260815-003）**：run 终止后其 pending `session_dialog_requests` 卡片由恢复路径作废——`cancel_pending_dialogs_for_run`（permission_service 模块级 helper，pending→cancelled、不自带 commit）在 `_cleanup_stale_runs_impl`（后端重启清 stale run）与 `_converge_crashed_run`（daemon 重启收敛）中调用；读侧兜底：session 级 `list_pending_dialogs` 与 workspace 级 `list_pending_dialogs_for_workspace` 均 join AgentRun 过滤非 ACTIVE_TURN_STATUSES 的孤儿卡（`list_dialog_history` 历史全量不受影响）；`respond_permission` 把 dialog 行解析提前到 current_run 检查前，终态卡直接返回明确 409/404（不再报笼统 no active run）。

## 注意事项

- **CLI 上行 naive 时间戳解释时区（ql-20260822-006）**：sillyspec CLI 上行的 `steps.completed_at`/`stages.started_at` 是 CLI 宿主机墙钟（`toLocaleString('zh-CN')`，无时区标记），后端归一到 UTC 一律按 `settings.cli_progress_timezone`（默认 Asia/Shanghai，env `CLI_PROGRESS_TIMEZONE`）解释——**禁止用 `naive.astimezone()` 随进程时区走**（Docker 容器 UTC ≠ CLI 宿主机时区，历史上致步骤时间线整体偏 8 小时）。解析入口 `ChangeService._normalize_completed_at`，时区串解析 `core/config.resolve_cli_tzinfo`（IANA 名或 ±HH:MM）。同类 naive 串新消费点出现时应复用同一配置，不要再发明第二种解释。
- 改动 backend 必须实测 API（curl 打端点），不能只靠 tsc/mypy，历史上出现过运行时未导入符号导致 500 的案例。
- Docker 部署时 backend 容器跑镜像内代码、不热重载，改源码后需 rebuild 镜像再验。
- 路由前缀约定：绝大多数在 `/api`，PPM 走 `/api/ppm`；新增模块要在 `main.py` 显式 `include_router`。
- 提交前需跑 `backend/.venv/bin/ruff format` 处理 staged 文件，否则 pre-commit hook 拦截。
- **scan 命令路径加引号**：`build_scan_bundle` 生成 sillyspec 命令（init/scan start/scan done）时 `--dir` 路径必须双引号包裹，防 Windows 反斜杠路径在 Git Bash 无引号时被转义吃掉（`C:\Users` 的 `\U` 被吞 → 路径变形/目录不存在）。
- **daemon-client spec 同步契约（D-005@v1，2026-06-26-daemon-client-spec-sync-fix）**：`platform-managed` workspace（`spec_workspaces.strategy`）的 spec_root 是扁平 `.sillyspec` 内容根，reader 经 `SpecPathResolver.for_spec_workspace(spec_ws)` 选 mode；`apply_sync` 接收 daemon tar 含 `.runtime`（push 非对称，pull `build_bundle` 仍排除）+ 落 `last_synced_at`/`sync_status=clean`；change-write 经 `daemon_change_writes` 表 lease-polling（`change_writer.proxy_create_change` + daemon `pending-change-writes`/`claim`/`complete` 三端点 + 60s 超时 gc），无在线 daemon 抛 `DaemonClientNoActiveSession`(400 `DAEMON_CLIENT_NO_SESSION`)。
- **runtime 实时读取链路（2026-08-19-runtime-live-daemon-read）**：runtime 模块 5 端点（`/runtime`、`/runtime/user-inputs[/raw]`、`/runtime/artifacts[/{filename}]`）数据源从容器直读 `spec_ws.spec_root` 快照切换为经绑定 daemon WS RPC 实时读取——`RuntimeLiveService` 经 `MemberBindingResolver.resolve_member_binding_or_none`（用户门控，D-004@v1）解析 daemon_id 后 `ws_hub.send_rpc` 调 `runtime.*` 四方法（独立命名空间，D-005@v1），35s 显式超时；daemon 失败不回退快照直接报错（D-001@v1）。进度经 sillyspec CLI 只读命令（D-002@v1，daemon spawn `sillyspec progress dump --spec-dir <specCacheRoot> --json`，输出 snake_case+ISO 契约）；用户输入/产物由 daemon 直读 `.runtime/` 下文件（D-003@v1）。错误映射 9 个 `Runtime*` 子类（离线 502/在途断连 502/超时 504/forbidden 403/not_found 404/版本过旧 method_not_found 422/产物超 1MB 413/其余 502），filename 预检（空/控制字符/绝对路径/../子路径）先于 RPC。旧 `RuntimeService` 快照读法整体删除。
- **SillySpec 进度同步契约（2026-08-10-sillyhub-platform-sync）**：`platform_sync` router **不自带 prefix**（路径写全 `/changes/...`，main 挂 `/api` 落地 `/api/changes/...`）——避开 FastAPI 对 `GET /changes` 的尾斜杠 307 redirect（客户端 `sync.js` 打无尾斜杠 `/api/changes`）。POST 409 必用 `JSONResponse` 绕过 `response_model` 校验，确保 body 严格按契约 §4.4（`{conflict,platform_progress,last_pushed_at}`，`platform_progress` 是平台当前 `latest_progress` 原样回显，**不 auto-merge** 客户端 body）。base_ts 比对用 ISO 8601 UTC **字符串字典序**（不转 `datetime`，契约 §7：字典序==时间序）。铁律 D-004：进度同步层永不触碰 `/api/workspaces/{wid}/changes/*` 派发层（无路径/数据重叠）。gen:types 须在主仓跑（worktree + editable install 坑：worktree 跑 `dump_openapi.py` 会加载主仓 `app.main` 不含本改动，须 `PYTHONPATH=<worktree>/backend` 或主仓合并后跑）。
- **进度首推占位建行 + reparse 镜像滞后保护（ql-20260815-002）**：`PlatformSyncService._ensure_change_row`——接受分支（首推/常规接受）后确保 `ux_changes` 有占位行（变更中心以 ux_changes 为主表 join 进度表，只写 `platform_change_progress` 会让镜像 tar 滞后期间新建变更在界面不可见）；`workspace_id=None`（shk_live_/JWT 全局 fallback）跳过、幂等、savepoint 撞 `ux_changes_workspace_key` 静默放弃、best-effort 不阻断上行。配套 `ChangeService.reparse` 全量删除环保护：CLI 最近上行仍报 `status=active` 且**无任何文档**的占位行不删（`_progress_reported_active_keys`，查询失败降级空集=无保护）；有文档的行仍以镜像磁盘为权威删除（防 stale progress 行让本地已删变更永生）。
