# 代码约定（Conventions）

> 子项目 **sillyhub-daemon**（本地任务执行守护进程，Node.js + TypeScript ESM）的代码约定。
> 事实来源：`sillyhub-daemon/tsconfig.json`、`sillyhub-daemon/package.json` 与 `sillyhub-daemon/src/`（64 个 .ts 文件）、`sillyhub-daemon/tests/`（143 个 .test.ts）实际代码，所有条目均经 Grep/Read 逐条核实，引用为 `file:line` 证据。
> Lint 仅 `tsc --noEmit`（package.json `typecheck`），无 eslint/prettier，约定靠 TS 编译选项与代码评审强制。

## 运行环境基线

- Node ≥ 20，ESM only（`sillyhub-daemon/package.json` `"type": "module"`；`sillyhub-daemon/tsconfig.json` `module`/`moduleResolution = NodeNext`）；TypeScript 5.5.4，target ES2022，`rootDir: ./src` → `outDir: ./dist`。
- `sillyhub-daemon/tsconfig.json` 开启 `strict`、`noUncheckedIndexedAccess`、`noImplicitOverride`、`forceConsistentCasingInFileNames`、`verbatimModuleSyntax`、`isolatedModules`（第 7-15 行），这几项直接决定下方"框架隐形规则"。
- 运行时校验 zod 4（`dependencies.zod: ^4.4.3`）；CLI 用 `commander`，HTTP/WS 用 `ws`，MCP 用 `@modelcontextprotocol/sdk`；包管理器固定 `pnpm@9.6.0`。
- `pnpm.overrides` 把 9 个平台的 `@anthropic-ai/claude-agent-sdk-*`（win32/linux/darwin × x64/arm64 × glibc/musl）全部重定向到统一的 `@anthropic-ai/claude-agent-sdk@0.3.181`（`sillyhub-daemon/package.json` 第 37-47 行），保证跨 Windows/Linux/macOS 一致。

## 框架隐形规则

这些规则不写在业务代码里，而是由 tsconfig / Node ESM / pnpm 工具链强制，踩坑直接编译或运行报错：

1. **相对路径 import 必须带 `.js` 后缀**（NodeNext ESM 要求，TS 不补全）：全仓 89 处/34 文件，如 `sillyhub-daemon/src/cli.ts`、`sillyhub-daemon/src/cmd-shim.ts:21`（`from './cursor-version.js'`）、`sillyhub-daemon/src/spawn-env.ts:23`。源码文件是 `.ts`，import 路径必须写 `.js`。
2. **Node 内置模块必须带 `node:` 前缀**：全仓 86 处/30 文件，如 `sillyhub-daemon/src/cli.ts`（`'node:fs'`、`'node:path'`）、`sillyhub-daemon/src/policy/path-utils.ts:12-13`。个别历史文件（如 `sillyhub-daemon/src/local-yaml-writer.ts:13-14` 用裸 `'fs'`/`'path'`）是遗留例外，新代码一律 `node:`。
3. **纯类型导入必须用 `import type`**（`verbatimModuleSyntax` 强制）：全仓 75 处/31 文件，如 `sillyhub-daemon/src/spawn-env.ts`、`sillyhub-daemon/src/model-error/classifier.ts`。值与类型混用时拆两条 import 或用 `import { X, type Y }` 内联。
4. **读 JSON 走 ESM import attributes**：`sillyhub-daemon/src/daemon-version.ts` `import pkg from '../package.json' with { type: 'json' };`（配合 `resolveJsonModule`）。
5. **`noUncheckedIndexedAccess` 下标访问返回 `T | undefined`**，必须收窄（判空或默认值）后使用，见 `sillyhub-daemon/src/local-yaml-writer.ts`（`lines[end]!` 收窄写法）。
6. **`sillyhub-daemon/src/api-types.ts` 禁手写，一律从后端 OpenAPI 生成**：文件头自声明 "auto-generated by openapi-typescript. Do not make direct changes"（`sillyhub-daemon/src/api-types.ts:1-4`）；生成入口 `sillyhub-daemon/package.json` scripts `gen:types`（`node scripts/gen-api-types.mjs`）与 CI 门禁 `gen:types:check`（生成后 `git diff --exit-code src/api-types.ts` 校验零漂移，`sillyhub-daemon/package.json:19-20`）。后端 schema 变更必须重跑 gen:types。
7. **per-server 配置隔离：`--server` 决定配置文件名**：配置文件路径由 server_url 驱动（`configPathForServer`），CLI `--server` 参数 > `DEFAULT_CONFIG.server_url`（兜底 `http://localhost:8000`）——不带 `--server` 启动会静默落到 8000 的 per-server 配置文件（`sillyhub-daemon/src/cli.ts:605`、`sillyhub-daemon/src/cli.ts:212`）。本地连非 8000 端口（如 8001）必须显式带 `--server`，否则读到的是另一份配置。
8. **local.yaml 写入走文本级顶层段替换**：只替换 `platform:` / `mcp:` 等指定顶层段，文件其余字节（注释/空行/其他段/CRLF）全保留——`sillyhub-daemon/src/local-yaml-writer.ts:35`（`findTopLevelSectionRange`）、`:70`（`replaceTopLevelSection`，null=删段）；CRLF 下 `'\r'` 留行尾重组原样还原（该文件 :29 注释）。禁止整文件重序列化（会删光用户注释）。
9. **LiteLLM master key 不下发 daemon、不落盘**：`litellm_proxy` 形态下 backend 只下发标记 + hub 代理地址（`<hub>/api/daemon/llm-proxy`），master key 不出 backend 进程（`sillyhub-daemon/src/credential-injector.ts:154`、`sillyhub-daemon/src/types.ts:304`）；daemon 侧把 daemon api_key 注入子进程 `ANTHROPIC_AUTH_TOKEN`，子进程 Bearer 打 hub 代理（`sillyhub-daemon/src/credential-injector.ts:26-28`、`sillyhub-daemon/src/cli.ts:676`）。daemon 任何代码不得持久化 master key。
10. **spawn env 是不泄漏铁律区**：`buildSpawnEnv` 返回值仅本地内存传给 `spawn({ env })`，禁止序列化到日志/Redis/HTTP 回传/磁盘/lease.metadata；任何 env 相关日志必须先经 `redactEnv`，禁止直接 `console.log(buildSpawnEnv(...))`（`sillyhub-daemon/src/spawn-env.ts:13-18`，R-09/R-02）。

## 代码风格

1. **tsc 严格模式是唯一静态门禁**：无 eslint/prettier，风格靠 `sillyhub-daemon/tsconfig.json` 严格 flag + 评审；提交前跑 `pnpm typecheck`（`tsc --noEmit`，`sillyhub-daemon/package.json:14`）。
2. **commander 链式命令定义**：`createProgram()` 内 `.command() → .description() → .option() → .action()` 一链到底，4 个命令 start/stop/status/logs（`sillyhub-daemon/src/cli.ts:387`）；option 描述写明格式与互斥关系（如 `--token` 与 `--api-key` 互斥，`sillyhub-daemon/src/cli.ts:387`）。action 函数独立导出（`startAction`/`stopAction` 等，`sillyhub-daemon/src/cli.ts:387/870`）便于测试直调。
3. **模块组织：一个职责一个目录，纯函数模块 + 文件头契约注释**。`sillyhub-daemon/src/adapters/`（协议适配）、`sillyhub-daemon/src/interactive/`（交互会话）、`sillyhub-daemon/src/policy/`（路径/文件系统策略）、`sillyhub-daemon/src/resilience/`（重试/容错）、`sillyhub-daemon/src/model-error/`（模型错误归类）各司其职；`sillyhub-daemon/src/model-error/index.ts` 只 re-export 类型，实现沉在 `classifier.ts`（`sillyhub-daemon/src/model-error/index.ts:2`）；`sillyhub-daemon/src/policy/path-utils.ts` 是无状态纯函数集（该文件 :1-9 模块注释声明"所有路径判断必须经过此模块"）。每个文件头部有职责 + design 决策编号（D-xxx/R-xxx/task-xx）注释，如 `sillyhub-daemon/src/model-error/classifier.ts:1-25`、`sillyhub-daemon/src/spawn-env.ts`、`sillyhub-daemon/src/local-yaml-writer.ts`。
4. **错误处理：分类器单一来源 + 纯函数归类**。可重试 HTTP 状态码集中在 `RETRYABLE_STATUS = new Set([429, 500, 502, 503, 504])`（`sillyhub-daemon/src/resilience/error-classify.ts:21`，判定在 :47），勿在调用点散落状态码判断；模型调用错误走 `model-error/classifier.ts` 纯函数归类（8 类、429 细分 quota_exceeded 不可重试 / rate_limited 可重试、无法识别兜底 unknown，`sillyhub-daemon/src/model-error/classifier.ts:15-22`）。异步一律 try/catch 包裹，可恢复副步骤 warn 后继续不中断主流程。
5. **结构化日志：事件名蛇形 + key=value 上下文**。Logger 接口 `debug/info/warn/error(event, kv?)`（`sillyhub-daemon/src/daemon.ts:381`），工厂 `createLogger` 输出 `[daemon.<event>] k=v`（`sillyhub-daemon/src/daemon.ts:381`）；事件名一律小写蛇形（`credentials_loaded` `sillyhub-daemon/src/credential.ts:96`、`audit_batch_failed` `sillyhub-daemon/src/cli.ts:222`）；cli 层无 daemon logger，构造轻量 logger 走 stderr 不污染 stdout（`sillyhub-daemon/src/cli.ts:220`）。业务点用注入的 `this._logger`，不临时新建。
6. **zod schema 集中在 MCP 边界**：全仓 17 处 z.object/z.string/z.enum 全部落在 `sillyhub-daemon/src/mcp-server.ts`——工具入参 schema 每字段 `.describe()` 兼顾校验与对外文档（如 dispatch_worker 的 `worktree_path`，`sillyhub-daemon/src/mcp-server.ts:60`）；schema 对齐 backend 请求模型（注释标 `mcp_tools.py` 来源）。MCP 工具用 `server.registerTool(name, { title, description, inputSchema }, handler)` 注册，共 5 个工具，构造与连接分离便于无 stdio 测试（`sillyhub-daemon/src/mcp-server.ts:60`）。
7. **Windows 兼容是显式工程**：npm `.cmd` 包装由专用解析器处理（git-bash 下 spawn .cmd 会 ENOENT，直接读 .cmd 提取真实 exe + prependArgs，`sillyhub-daemon/src/cmd-shim.ts`）；路径规范化收口 `normalizePath`（strip 引号 + git bash `/x/`→`X:/` + resolve 折叠 `..`，UNC 路径单独标记，`sillyhub-daemon/src/policy/path-utils.ts:17-45`）；YAML 段替换 CRLF 原样保留（`sillyhub-daemon/src/local-yaml-writer.ts`）。
8. **命名约定**：类/接口/类型 PascalCase（`Daemon`/`SessionManager`/`ClassifyModelInput`）；函数/变量 camelCase（`loadConfigFn`/`createProgram`）；常量 UPPER_SNAKE_CASE（`RETRYABLE_STATUS`/`UNC_PREFIX`/`UNC_REJECTED`）；私有成员 `_` 前缀（`this._logger`，`sillyhub-daemon/src/daemon.ts:849`）。
9. **测试放独立 `sillyhub-daemon/tests/` 目录镜像 src 结构**：不 colocate（src 下 0 个 .test.ts），143 个测试文件按 `sillyhub-daemon/tests/adapters/` `sillyhub-daemon/tests/interactive/` `sillyhub-daemon/tests/policy/` `sillyhub-daemon/tests/resilience/` `sillyhub-daemon/tests/model-error/` 镜像 src 子目录（如 `sillyhub-daemon/tests/model-error/classifier.test.ts` 对应 `sillyhub-daemon/src/model-error/classifier.ts`）；共享夹具在 `sillyhub-daemon/tests/helpers.ts` 与 `sillyhub-daemon/tests/helpers/fake-child.ts`；vitest 跑法 `vitest run --passWithNoTests`（`sillyhub-daemon/package.json:15`）。

## 典型模式（可直接套用）

1. **纯函数策略模块**：`sillyhub-daemon/src/policy/path-utils.ts` —— 模块头声明唯一入口，导出无状态纯函数 + sentinel 常量（`UNC_REJECTED`），实现零副作用便于单测（对应 `sillyhub-daemon/tests/policy/path-utils.test.ts`）。
2. **MCP 工具注册**：`sillyhub-daemon/src/mcp-server.ts:348` —— `createMcpServer(client)` 工厂返回未连接的 server，工具名 + title/description + zod inputSchema（字段全 `.describe()`），schema 字段注释标 backend 对齐来源（`backend/app/modules/agent/mcp_tools.py`）。
3. **凭据注入隔离**：`sillyhub-daemon/src/credential-injector.ts` —— 模块级状态 `_daemonApiKey`（`setDaemonApiKey`/`getInjector`），litellm_proxy 形态只注 hub 代理地址不碰 master key（:122-133），与 `sillyhub-daemon/src/spawn-env.ts` redact 守卫配套成不泄漏闭环。
4. **per-server 配置定位**：`sillyhub-daemon/src/cli.ts:599` —— `opts.server ?? DEFAULT_CONFIG.server_url` 决定 `configPathForServer` 文件名，opts.server 同时覆盖落盘值保证定位与持久化一致。
5. **错误归类纯函数**：`sillyhub-daemon/src/model-error/classifier.ts` —— 输入接口对齐真实数据流（isError/resultText/apiRetryError/assistantStdout/stderrText），按关键词归类 8 类 + 中文 hint，unknown 兜底不抛异常，接线与归类分离（task-02 归类 / task-03 接线）。
