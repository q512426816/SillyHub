## BA · 做什么（业务）

**40+ 能力，5 大域**：项目空间与运行时 / 变更托管（SillySpec）/ Agent 编排 / 凭证治理 / 治理合规；外加已上线的 PPM 项目管理。

**两条主线在 execute 阶段交汇**——这是最该画的一张图：

```
变更托管主线（文档驱动）        Agent 编排主线（任务执行）
 brainstorm 想清楚                 建 mission
    ↓ 拆任务                         ↓ 派发
   plan                              ↓
    ↓ ┌──────── execute 交汇 ────────┘
    ↓ ↓ 每个阶段派发 = 一次 agent run
   verify 验收                      daemon 执行 + 收敛
    ↓                                 ↓
   archive 归档 ←── 进度回灌对账 ────┘
```

→ 领导要的「4A 管理」就在这条链里：**先想清楚→拆任务→实现→验收→归档，每步有产出、有校验、可追溯**。这不是哪个平台的专利，咱用流程纪律实现了，而且文档与代码绑定。

## DA · 用什么数据（数据）

**PG 77 张表 / 11 个域**（SQLModel + asyncpg）+ Redis 缓存 + MinIO 对象存储 + spec 文档资产树。

**关键卖点——文档即数据，双源对账**：

```
   spec 文档资产（design/plan/tasks/scan）      ← 意图
              │  platform_sync 同步层
              ▼
        ┌──────────┐         ┌──────────────┐
        │ 平台 PG  │ ◄────► │ daemon 落盘代码│  ← 真相
        │ 进度库   │  对账   │ (git worktree) │
        └──────────┘         └──────────────┘
              base_ts 字典序乐观锁：冲突 409 绝不 auto-merge
```

→ 「不两张皮」的机制保证：意图和实现对不上时系统报冲突让人介入，而不是静默漂移。凭证全量 **xchacha20 加密**入库；权限缓存带熔断降级（Redis 挂了回查 DB，鉴权永不因缓存失败）。

## AA · 怎么做（应用）

**四进程协作**——平台只编排，daemon 才是真执行体：

```
   浏览器 ──► frontend(Next.js) ──► backend(FastAPI) ──编排/治理──┐
                          │  WS+SSE                            │
                          │                          ┌──────────┴──────────┐
                          ▼                          ▼                     ▼
                     用户看进度/审批          daemon(Node,用户自己机器)   LiteLLM 网关
                                              ↑ 真正跑 agent CLI          协议转换
                                              │ agent 在这，数据不出企业
                                              └ spec 同步/凭据注入/策略沙箱
```

**Agent 编排引擎**：single（GLM 预拆）/ team（主 agent 动态派 worker）/ external 三模式；worker 各自独立 git worktree 并发写不互覆；收敛用 R5 原子抢占杜绝重复 finalize。**两套 MCP 物理隔离**：对外 12 工具（第三方经 token）、daemon 内置 5 工具（注入主 agent）。

→ 「平台只编排不执行」= backend 进程和 agent 执行隔离，**故障域分离 + agent 永远在用户自己机器上跑**。

## TA · 在什么上做（技术）

**Docker Compose 7 服务**，全是标准开源，无供应商锁定：

```
   ┌──────────────────────────────────────────────┐
   │  frontend │ backend │ litellm │ litellm-db    │  ← 应用层
   ├──────────────────────────────────────────────┤
   │     postgres(PG16)   │   redis(7)   │  minio  │  ← 基础设施
   └──────────────────────────────────────────────┘
           三重隔离：workspace ＋ per-member daemon ＋ git worktree
```

- **门禁四道**：pre-commit(ruff) / backend-CI(ruff+mypy+pytest) / frontend-CI(lint+tsc+vitest) / scan-drift（文档漂移检测）。
- **安全**：三密钥必填启动 + SSRF 防护 + RBAC + 审计 + 弱口令黑名单 + 登录限流。
- **跨平台**：Win/Linux/macOS 全兼容，本地/阿里云 Docker 部署。

→ 「资产不被锁定」的根：PG/Redis/MinIO/LiteLLM 全是开源标准件，代码在 git，daemon 在自己机器。**哪天不续任何人的费，系统照跑、代码照接、人照维护。**
