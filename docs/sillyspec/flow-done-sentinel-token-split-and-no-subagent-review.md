# flow done 哨兵 token 拆分与无子代理环境评审代行（2026-10-08-turn-nav-hover-mark 实证）

状态：活跃坑（待工具修复）。

## 1. 哨兵证据 token 不拆连写斜杠组

**现象**：实现一次提交覆盖多个任务时，提交消息写 `task-01/02/03`（自然语言习惯），flow done 哨兵按**独立完整 token**（如 `task-02`）匹配区间提交标题/正文——连写组只命中首个 `task-01`，其余判定「零完成证据」拒收：

```
🚫 哨兵断言拒收：tasks.md 全勾（5/5）但 2 个任务零完成证据（区间提交标题与正文均无 token…）：task-02、task-03
```

**绕过**：补一笔 `--allow-empty` 证据提交（消息带 `task-02`、`task-03` 独立 token，正文注明指向原实现提交）。可行但产生空提交噪音。

**建议**：哨兵匹配时对斜杠/顿号/逗号连写组做归一化拆分（`task-01/02/03` → task-01、task-02、task-03），或在 flow start 横幅/拒收文案里明示「每任务须独立 token，禁连写」。

## 2. 无已注册子代理环境评审无法按任务书执行

**现象**：flow done 判需独立评审时任务书要求「起一个干净上下文的子代理执行」，但宿主环境 agents 目录为空（无任何已注册代理）时无法照做；sillyspec 无 `--skip-review` 类逃生参数（flow done --help 无相关项）。

**绕过**：主会话按任务书检查单代行自审，review.json 的 reviewer 字段如实标注 `inline-self（环境无已注册子代理…）`——工具接受该产物（评审通过）。但「干净上下文」的独立性承诺打了折扣，属环境能力缺口下的降级。

**建议**：①CLI 检测无子代理通道时给出显式选项（等待 / 代行留痕 / 降级门档）；②文档化 reviewer 字段的代行标注惯例。
