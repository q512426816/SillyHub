# flow done「design 问题行机器回填」向四问节注入倒序重复问句行

> 记录时间：2026-10-13 · 来源变更：2026-10-13-turn-live-visibility（复审实证）
> 状态：活跃坑（有确定性绕过，待工具修复）

## 现象

flow done 子步输出「[design 问题行机器回填] design『…』问题行曾被改写——已按锚回填原文
（agent 作答保留）」后，归档 design.md 的「边界与并发」节出现 **4 行倒序（4/3/2/1）
重复问句行**，紧接 agent 的 1-4 编号回答行——问句语义与回答行前缀完全重复，编号倒序
穿插造成阅读错乱。「做法概述 / 接口契约 / 风险与死路」三节的单行锚问句是 flow start
骨架既有结构（正常），仅四问节的批量回填异常。

实证：2026-10-13-turn-live-visibility 复审（review.json superseded 记录）发现 7 处
问句行，其中 4 处为本坑（归档 design.md 28-31 行倒序重复）；该变更归档后已人工清理。

## 根因

机器回填按「问题锚原文」逐条回填，但 agent 的四问回答行本身已带「N. 问题短语：答案」
形态——回填器未识别回答行前缀已含问句锚语义，仍把四条问句独立注入；注入顺序倒序
（疑似 Map/集合遍历序）叠加在 agent 回答之前。

## 影响

- 归档件（文档真相面）出现重复噪音与编号错乱，读者需自行辨认哪组是答案；
- 后续 change 复用/对照该 design 时锚比对易混淆。

## 绕过

- 收口后人工清理归档 design.md 中与回答行前缀重复的注入问句行（change.patch 已按
  sha256 冻结，清理展示面不影响审计件）；
- 写 design 四问时回答行保持「N. 问题短语：答案」形态（现状惯例），识别注入行=>
  出现独立成段、无答案跟随的纯问句行。

## 待工具修复

机器回填器识别「回答行前缀已含问句锚」时跳过注入；或四问节改为只校验不回填
（骨架问句仅 flow start 期存在，收口期以回答行编号前缀为锚）。

## 处置记录（2026-10-14）

**已修**（sillyspec 仓工作树，未提交）：`verifyThinDocsV2` 的问句在场判定放宽——
`questionPresent`（新助手）认三种形态：整行相等（骨架原样）/**行内包含锚原文**
（剥一层列表/编号前缀后 includes——「N. <问句>：答」形态，坑现场）/两者皆无（真改写）。
在场 → 跳过回填且不拒收（问句语义已保留在回答行前缀）；真改写仍走既有回填注入链。
「只剥一层前缀」是调试实证的修正点：锚问句自带「N.」编号，多层剥会把锚编号一并
吃掉致包含判定假阴性。
