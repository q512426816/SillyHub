# quick --cancel 对轮转后的 QUICKLOG 归档条目失明（空壳会话无法清理）

- 状态：活跃（工具侧待修）
- 发现：2026-09-16（ql-20260916-001-5852 收尾时实测）

## 现象

`quick --done` 时 CLI 提示 N 个疑似空壳会话，建议 `sillyspec run quick --cancel --change <会话ID>` 清理。
实际执行 `--cancel` 全部失败，两种报错：

1. `取消失败: 未在任何 QUICKLOG 文件找到条目 ql-<ID>`——条目在**轮转归档文件**里
   （如 `QUICKLOG-qinyi-2026-09-15.md`、`QUICKLOG-qinyi-2026-09-11.md`），`--cancel` 的条目定位
   只扫活跃 `QUICKLOG-<user>.md`，轮转一发生历史条目就永久不可达；
2. `无法定位会话 <id> 的 qlId（guard.json 缺失/损坏）——显式传 --ql <ql-xxx>`——但该会话
   从未成功写入过任何 QUICKLOG 条目（启动即被 `--input` 缺失校验拒绝），没有 ql-ID 可传，
   提示的建议在逻辑上不可执行。

## 影响

- 空壳会话残留只是启动提示噪音（advisory），不阻断任何流程；
- 但「提示清理 → 清理必失败」的死循环每次 `--done` 都重复出现，提示逐渐失去可信度。

## 修复建议（工具侧）

1. `--cancel` 的条目查找范围扩到 `quicklog/` 目录全部 `QUICKLOG-*.md`（含轮转归档）；
2. 取消语义放宽：空壳会话（零步骤完成 + 无 QUICKLOG 条目）直接清进度即成功，不要求
   条目可达——条目定位只对「有条目但未翻完成」的会话才有意义；
3. guard.json 缺失的分支：报错里给出「该会话确无条目，可用 --force 跳过条目清理」的逃生门。
