# spec-sync 冲突只给「用本地覆盖」和「放弃」两个选项，缺「接受服务器」——本地归档落后时无安全收敛路径

- **日期**：2026-09-03
- **状态**：活跃（工具缺陷，待修复）
- **影响命令**：`sillyspec run quick`（每次 CLI 调用都会触发 spec-sync 检查并刷屏）

## 现象

quick 会话（quick-1b00c2c0）启动后，每次执行 `sillyspec run quick ...` 都输出两条告警：

1. 「拦下 4 个旧副本回推（本地自上次同步未改动而服务器已前进）」——ROADMAP.md 等 4 个文件，这条是**安全**的（没有推送，行为正确）。
2. 「检测到 spec 树冲突（164 个文件，服务器版本 …）」——全部是 `changes/archive/2026-08-2x-*/**` 归档文档，服务器版本号（10~23）高于本地。处置提示只有：
   - `sillyspec platform resolve <change> --keep-local`：以本地为准重推——**用旧版本覆盖服务器新版本**，会把别人（或另一台机器）已归档推进的内容回滚；
   - `--abort`：放弃本次同步——本地不变（安全但冲突永不收敛，每次命令继续刷屏 160+ 行 JSON）。

## 期望

服务器已前进、本地未改动的文件，应该有「接受服务器版本（拉取覆盖本地）」的收敛选项；至少 `--abort` 后不该在每次后续命令里重复全量打印冲突 JSON（一条摘要 + 详情落文件即可）。

## 绕过

当前只能 `--abort` 跳过同步（本地功能不受影响，QUICKLOG/进度文件仍正常落盘）。归档文档的本地副本持续落后，等工具提供 accept-server 后一次性收敛。
